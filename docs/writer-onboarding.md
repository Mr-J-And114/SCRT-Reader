# SCRT 写手入门与交接说明

整理日期：2026-09-30。面向首次参与项目的写手，**只需接收这一份 MD 即可阅读入门资料**。系统概况、角色资料、剧情现状、工作流程、交付模板、格式说明和当前 Day 0 全文均在本文件中。不需要访问项目目录或另开其他文档。设定疑点交由负责人确认。

## 1. 这是什么游戏

SCRT-Reader 是使用 Godot 4 制作的 SCP 主题终端叙事游戏。玩家扮演海岛观测站操作员，面对一台带 CRT 效果的旧式终端，通过工作、通讯、邮件、文件、监控和无线电接触故事。

当前主线配置使用 **Site-514／SCRTs 海域通信与雷达遥测站**。旧设计文档中的 OB-7K、早期角色阵容和具体剧情大纲属于历史草案，遇到冲突先确认。

游戏主要依靠阅读、倾听、观察与少量选择推进。工作数据、文件措辞、角色回应及不同渠道之间的矛盾都可以成为线索。终端是玩家接触世界的主要窗口，写作时应说明玩家通过什么渠道获得信息。

旧设计提出“日常工作 → 发现异常 → 逐步接近真相”的结构，参考 VA-11 Hall-A 用日常工作承载人物与故事的方式。28 天、五幕及四种结局是完整版草案，尚不能视为已完成或全部定稿。

## 2. 当前目标与开发分工

当前目标是 **七天试玩版**。剧情由写手推进，负责人正在优化已有系统。Day 0 是已接入的教程日，当前主线文件含 Day 0 对话与邮件；Day 1 起主要是通用配置，不能据此认为七天剧情已经全部接入。

“七天”是否包含 Day 0，以及各天最终事件、试玩收束点，需要负责人统一确认。写手不要自行把旧 28 天草案的前七天确定为本次试玩剧本。

写手优先交付可阅读、可审阅的中文剧本与事件表，不必先学 GDScript 或自行打包。通过审阅后，再将正文转换成 JSON、文本文件及故事包。当前已接入的教程文字、邮件、分支条件见本文件末尾附录，可以直接据此了解人物口吻与玩家已知内容。

## 4. 玩家的一天与叙事渠道

现有流程大致为：开机登录 → 晨间通讯／邮件 → 环境监测 → 自由探索与任务 → 保存退出。当前正常跨日与登录、环境任务完成情况有关；不要在剧本中默认已有“结束值班”按钮。

| 渠道 | 适合承载的内容 | 写手需要提供 |
|---|---|---|
| 通讯／电话 | 人物关系、指令、争执、即时反应 | 角色、逐句台词、触发条件、接听方式、选项和后续 |
| 多人会议 | 人物之间的冲突或协作 | 在场名单、站位、发言顺序、进入和退出时机 |
| 邮件 | 正式通知、私人来信、附件任务 | 发件人、标题、正文、投递条件、是否永久保存 |
| 文件／Vdisc | 报告、日志、调查证据、解密任务 | 文件目录、正文、可见条件、密码线索、交付要求 |
| 环境监测 | 日常基准、天气变化、异常征兆 | 数据变化、玩家可发现的证据、角色回应及后果 |
| CCTV | 空间线索、设备或场景变化 | 摄像头位置、画面变化、出现时机与素材需求 |
| 无线电 | 广播、未知信号、摩斯码、SSTV 图像 | 信号内容、频率需求、发现条件、译文／图像需求 |
| 个人档案／绩效 | 工作反馈、身份和权限信息 | 加扣分原因、发生时机、面向玩家的解释 |

同一事件可通过多个渠道展开，但每个渠道应提供新的信息或新的视角。关键线索需要记录发现位置与后续用途；可错过的内容应注明是否有补救入口。

## 6. 一段剧情怎么交付

每个场景建议使用下面的交付模板。可以用 Markdown、Word 或共享文档，格式统一即可。

```text
场景 ID：由负责人统一分配，例如 d1_场景名
日期／阶段：
场景目的：推进什么信息或人物关系
入口：登录／读邮件／扫描完成／读文件／拨号／其他
前置条件：需要看过什么、做过什么选择
参与角色与显示方式：单人卡片／多人会议／简报
正文：按角色逐句写，必要动作与停顿另作注释
选项：玩家看到的文字；每项对应的完整后续
结果：标记变化、邮件／文件投递、绩效变化
退出与补救：拒接、错过、中断后如何处理
素材需求：立绘动作、图片、音效、监控／广播资源
待确认：尚未定稿的设定与系统需求
```

每日再汇总一张事件表：开场、必经工作、主事件、可选探索、收工条件、次日承接。旧设计建议每日约 3～5 个新内容点，可作为初始参考，再由试玩节奏调整。

分支需要交付后续内容或明确汇合点。密码与解谜需同时交付答案、线索分布及失败后的提示路径。角色台词、玩家选项、系统提示和幕后注释要分开，避免幕后信息意外展示给玩家。

## 7. Day 0 发生了什么，以及哪些信息已经告诉玩家

Day 0 在当前剧本中是周六教程日，下一天为周日。基本顺序如下；完整文字保留在附录，以下仅整理阅读顺序。

1. 注册／登录后，神田玲先联系玩家，确认到岗，投递欢迎邮件。她曾在这里值班，知道玩家没有得到充分培训，并预告一位大人物即将接管通讯。
2. 阅读欢迎邮件后，Ava 来电，自报身份并宣布接管站点。玩家选择回应或沉默；沉默分支提高 `anger_ava`，出现被打断的“Si——”称呼。
3. Ava 布置岗前热身任务，通过第二封邮件要求玩家熟悉邮件、环境监测和通讯。
4. 神田请求接入，玩家可允许或拒绝；允许时进入多人会议，两人争论教学与验收职责，最后确定“教学归神田，验收归 Ava”。拒绝接入与直接拒接电话是不同分支。
5. 玩家完成首次环境扫描后，可收到神田的教学小结。
6. 玩家主动拨给 Ava 汇报，按当日环境任务是否完成进入成功或失败分支。成功获得绩效；失败被告知缺额需要补回。
7. Ava 展示单人通话、多人会议和简报模式，神田随后提醒收工、保存，并建议睡不着时调无线电。

这部分建立了孤岛操作员、远程指导、上级监督、工作考核和人物之间的职责冲突。欢迎邮件明确说玩家目前是岛上唯一的人类，但岛屿具体结构、非人存在及这句话的真实边界不能由写手自行扩展成定论。

“Si——”、前辈值班经历、系统监控、Ava 安排岗位等都是当前文字中的信息或潜在线索。本文没有它们的最终解释，不应直接替项目揭晓。

邮件教程已同步：`env` 打开，输入 `scan` 采集并查看摘要，输入 `report` 提交。旧 `env scan` 仍可启动采集，`env read`／`env anomaly` 进入观测台；完成回电在提交并退出观测台后播放。

## 8. 各系统的具体写作规则

### 通讯、选项与会议

通话可以静默接入、强制接听或允许玩家接听／拒接。需要安排拒接后果、错过后的回拨或其他补救方式；关键主线不能只交付“接听成功”的内容。

目前角色台词逐字显示，并使用角色各自的短音模拟说话；不是完整台词配音。停顿和标点会影响听感，避免连续大量省略号、重复符号和过长单句。音色可实时调节，但不是写手必须处理的工作。

多人会议使用左、中、右站位，当前发言者切换到前景。角色进入、离开、动作和图片展示要另外注明。超过三人如何排布需要接入确认。长时间场景应标明何处结束，避免持续占用通讯界面。

选项请编号并交付每项后续、汇合点及记录值。当前普通选项可以等待玩家选择；限时选项还未加入，不能以此作为试玩剧情成立的必要条件。

### 邮件与文件

邮件需写明：ID、发件人、标题、正文、投递时机、临时或永久、附件任务。当前临时邮件与全局邮件分开管理，教程对玩家说明临时邮件次日清除、全局邮件永久保存。投递时机可以与场景衔接，读某封邮件也可以触发通讯。

文件需写明虚拟路径、文档类型、可读条件、密码及线索。可用报告、邮件、聊天记录和双页文档等展示形式。文本中允许标题、段落、颜色、图片以及数学公式；涉及特殊排版先给出意图，接入方负责实现。

正文展示给玩家，交付注释给制作人员：报告中的作者知识、玩家能够知道的事实和幕后真相应分开。必要线索不要仅依靠一闪而过的特效。

### Vdisc 调查盘

`.scp` 故事盘本质是装有配置与内容文件的 ZIP 包，可模拟收到的调查资料。玩家领取的是个人副本，后续阅读、文件修改和任务状态以个人副本管理。

当前任务可以检查阅读比例、特定文件、文件数量和数据量。写手应设计有意义的调查与交付，不必把底层指标直接写成任务故事。修改文件的具体内容和方式需要与负责人确认。

每项任务交付：发布人、领取邮件／号码、盘内文件目录及正文、目标证据、通过条件、上交对象、成功反馈、缺内容时提示、错误收件人后果、奖励、重新领取后如何处理。错误收件人可以退回或没收；具体结果由任务配置决定。

系统联调样例：`demo_site19`，发布人神田，正确上交号码 `1001-0002`，下载入口号码 `9900-0002`，要求阅读至少 20%、存在 `/reports/summary.txt`、可见文件至少 8 个、数据至少 1 KB。成功给支线绩效 1 分；交给 Ava 的 `1001-0001` 会被没收并给主线绩效 1 分。这些是测试配置，不能当作普遍规则或正式剧情安排。

### 环境、监控与无线电

环境系统有大气、海洋、地球物理、大气成分四类数据，共 21 个传感器，以及露点、体感温度等派生参数。可写气温、湿度、气压、风、降水、能见度、海温、潮汐、浪高、盐度、磁场、辐射、地震、氧气和二氧化碳等变化。可展示设备故障、天气联动与异常事件，但具体物理解释和剧情事件先经审核。

当前模拟部分依赖真实系统时钟。把关键线索安排成现实凌晨必须上线、长时间等待或连续真实天数才能触发，会产生体验和接入问题；关键剧情条件应优先按游戏天数或明确玩家行为规划。

监控需提供镜头对应地点、正常基准、变化前后、出现条件、可观察线索和素材说明。环境异常与画面异常可互相印证，但不要默认系统能自动理解写手描述并生成画面。

无线电支持摩斯码、SSTV 图像与音频信号。交付时同时给原始内容、玩家最终应解读的内容、发现条件、提示与后续用途。若要用录音、图像或音效，附素材清单。

### 绩效与剧情变量

当前绩效分主线、日常、支线，以及奖励／扣分；默认当日配额为 3，可按日覆盖。未达标产生缺口，后续正分先补缺口，剩余才计入当前分类；累计分与今日达标分因此可能不同。系统会周期性寄送报告并升级警告，但最终结局和人物关系并非自动完整实现。

Day 0 自动环境任务加分被关闭，主要通过对话行中的剧情动作给分。现有教程以接触 Ava、首测反馈、成功主动汇报等场景记录分数。不要把复测或重复播放自动设计成可反复领取奖励的路径。

当前已声明的剧情变量如下。名称能够说明用途方向，不能替代未取得的完整变量策划表。

| 变量 | 初始值 | 当前可确认的用途或边界 |
|---|---|---|
| `anger_ava` | 0 | Ava 相关不满计数，Day 0 沉默分支累加 1 |
| `rel_nanami` | 0 | 七海关系相关预留值，完整增减规则未提供 |
| `vdisc_damaged` | false | 磁盘损坏相关预留标记 |
| `nanami_betrayed` | false | 七海相关分支预留标记，具体事件未提供 |
| `tsingtao_progress` | 0 | 预留进度值，本文没有对应设定解释 |
| `overtime_penalty` | false | 加班／处罚相关预留标记 |
| `prev_clue`、`prev_hint` | false | 前任线索相关预留标记 |
| `s0_heard`、`s1_heard`、`s2_heard` | false | 信号听取相关预留标记，具体信号内容未提供 |
| `termination_eligible` | false | 解雇资格相关预留标记 |

新变量应写明含义、类型、初始值、设置时机、读取条件及清除时机。选项记录与关系数值分别管理；不能默认“选项 1”就增加好感。

## 10. 接入格式速查：不懂程序也可以只交中文稿

内容大体装在一个主线清单或故事包里：故事信息、角色、每日触发、对话、邮件、文件、任务及素材。`.scp` 包内含 `manifest.json` 和正文／素材文件；负责人负责打包和接入。以下示例是格式模板，方括号中的占位内容要替换，不是新增正式剧情。

### 一个最小对话与分支

```json
{
  "comm_dialogues": {
    "sample_scene": {
      "title": "[场景标题]",
      "callable": false,
      "repeatable": false,
      "lines": [
        {
          "character": "kanda",
          "text": "[台词与问题]\n[1] [选项一]\n[2] [选项二]",
          "wait_for": "choice:sample_scene_q1"
        }
      ]
    },
    "sample_scene_a1": {
      "title": "[选项一后续]",
      "callable": false,
      "repeatable": false,
      "next": ["sample_after"],
      "lines": [{"character": "kanda", "text": "[选项一回应]"}]
    },
    "sample_scene_a2": {
      "title": "[选项二后续]",
      "callable": false,
      "repeatable": false,
      "next": ["sample_after"],
      "lines": [{"character": "kanda", "text": "[选项二回应]"}]
    },
    "sample_after": {
      "title": "[汇合场景]",
      "callable": false,
      "repeatable": false,
      "lines": [{"character": "ava", "text": "[后续台词]"}]
    }
  }
}
```

当前分支处理会把选择记录为字符串 `"1"`、`"2"` 等；示例中的 `sample_scene_q1` 对应首选分支名 `sample_scene_a1`、`sample_scene_a2`。Day 0 还使用其他兼容命名，因此新场景建议保持上述统一格式，由接入方核对。

| 字段 | 含义与使用位置 |
|---|---|
| `character`、`text` | 行级：角色 ID 与台词，`{username}` 可替换为玩家用户名 |
| `callable` | 对话级：是否供主动通讯选择；不能单凭此字段假定已有号码路由 |
| `repeatable` | 对话级：是否允许重复播放，有奖励的场景需要防重复领取 |
| `call_mode` | 对话级：`forced` 强制来电，`answerable` 可接听来电；普通静默续播也可用 |
| `reject_consequence` | 对话级：拒接后的动作，例如转入指定后果场景 |
| `next` | 对话级：后续场景 ID 数组，需避免重复续播或循环 |
| `deliver_mail` | 对话级：关联已配置的场景邮件 ID |
| `requires_mail` | 对话级：供读邮件触发筛选的邮件 ID |
| `requires_flag` | 对话级：要求指定剧情标记满足值 |
| `requires_choice` | 对话级：要求某次选择记录满足值，例如 `"sample_scene_q1": "1"` |
| `requires_tasks` | 对话级：`all` 或 `incomplete`，指当前环境任务和日报完成情况 |
| `flags_add` | 对话级：对指定数值标记累加，不是通用好感系统 |
| `wait_for` | 行级：等待选项或条件。选项格式如 `choice:sample_scene_q1` |
| `display_mode` | 行级：`card`、`meeting`、`presentation` |
| `meeting_slot` | 行级：`left`、`center`、`right` |
| `expression`、`action` | 行级：表情／角色动作，需有对应素材与实现 |
| `auto_next` | 行级：自动续句延迟秒数，正文未配置时通常等待玩家推进 |
| `screen_effect` | 行级：已接入的画面效果，例如 `glitch`、`shake`、`noise`、`blackout`、`tear` |
| `story_action` | 行级：剧情动作字符串或数组，例如 `score:1:daily` |
| `slide_image`、`slide_hide` | 行级：简报图片展示／隐藏，需要对应素材 |

不要使用旧指南中的 `condition` 来代替当前 `wait_for`。当前播放器实际打字节奏主要读取角色声音配置，不能仅靠填写行级 `speed` 保证预期效果。台词行 `sound` 的播放函数目前为空，音效需求应交接给负责人，通过已有音效入口接入。

每日可配置的主要触发入口是登录开始、扫描完成、检测到异常、读邮件、执行命令等。写手只需说明触发意图，技术人员将其转换为 `on_start`、`on_scan_complete`、`on_anomaly`、`on_mail_read`、`on_command` 等配置。不要把“已写入配置”视为所有玩家路径都已验证。

格式常识：JSON 使用英文双引号；不能带注释或末尾多余逗号；换行写 `\n`。展示文字可用 `[b]粗体[/b]`、`[color=#ffcc00]文字[/color]`；特殊效果请另作制作注释。公式可提出行内／独立成段需求，接入时使用 `[math]...[/math]` 或 `[math block]...[/math]`。

## 11. 七天试玩版与完整版草案的边界

旧完整版草案分为适应期（1～3 天）、初兆（4～7 天）、暗涌（8～14 天）、真相（15～21 天）、结局（22～28 天）。候选线索包括微小读数偏移、磁场脉冲、未知广播、加密目录、前任日志和总部指令矛盾。这些只能作为讨论素材，不是本次试玩版必须采用的事件。

旧稿四种结局方向为服从、发现后沉默、对外揭露、理解接受，设想与信息发现、关键选择和隐藏任务有关。当前没有完整结局判定实现，也没有确认七天试玩如何收束；新写手应先完成自己负责的场景及线索承接，不自行决定核心真相和最终结局。

七天试玩版优先保证：玩家能理解自己的工作、记住主要人物、发现至少一条有后续价值的疑问、完成一段可回顾的任务体验，并知道试玩结束时哪些问题仍未解答。具体事件密度与收束由负责人审阅。
