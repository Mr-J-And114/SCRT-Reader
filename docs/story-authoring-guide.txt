一、项目概述
================================================================

  SCRT-Reader 是一个模拟 CRT 终端的叙事游戏。

  玩家扮演一名被派驻到偏远海岛观测站的环境监测操作员，
  每天的工作是启动终端、运行环境扫描、查看数据、阅读
  邮件和文件。

  随着天数推进，玩家会逐渐发现：
  · 环境数据越来越不对劲
  · 总部的回复越来越敷衍
  · 这座"气象站"背后隐藏着秘密

  灵感来源：VA-11 Hall-A（用"日常工作循环"驱动故事推进）。
  核心体验：玩家是"倾听者和观察者"，通过工作和探索
  逐步揭开真相。

  游戏引擎：Godot 4（GDScript）
  故事数据：纯 JSON + 文本文件，打包为 .scp（ZIP）

二、游戏世界观与每日流程
================================================================

  每一天 = 一个"轮班"。流程如下：

  ┌─────────────────────────────────────────────┐
  │  1. 开机启动                                │
  │     → 系统自检 → 显示日期和天气             │
  │     → 晨间通讯（AVA 或其他角色主动联络）    │
  │                                             │
  │  2. 例行工作                                │
  │     → 玩家输入 env scan 执行环境检测        │
  │     → 约 20-30 秒的扫描动画                 │
  │     → 扫描报告 + 异常标记                   │
  │     → 如果发现异常，角色会发起对话反应      │
  │                                             │
  │  3. 自由探索                                │
  │     → 阅读新解锁的文件                      │
  │     → 查看新邮件                            │
  │     → 拨号联络角色                          │
  │     → 使用无线电接收器                      │
  │     → 查看环境仪表盘（env view）            │
  │                                             │
  │  4. 关闭终端                                │
  │     → 自动存档                              │
  │     → 下次启动进入下一天                    │
  └─────────────────────────────────────────────┘

  重要设计原则：
  · "工作"本身有仪式感，不是纯粹的跳过障碍
  · 每天 3-5 个新内容点就够了，不要让玩家觉得看不完
  · 随着天数推进，扫描结果本身变得越来越"不对劲"

三、主线剧情结构
================================================================

  三层叙事结构
  ──────────────────────────────────────────

  ┌─────────────────────────────────────────────┐
  │  第一层: 表层 —— 日常工作                   │
  │  "我是一名前哨站操作员，负责记录天气数据"    │
  │                                             │
  │  第二层: 中层 —— 异常与疑问                 │
  │  "这些数据不对劲，总部的回复也很奇怪"       │
  │                                             │
  │  第三层: 深层 —— 真相                       │
  │  "这座岛上藏着不为人知的秘密"                │
  └─────────────────────────────────────────────┘


  章节结构（共约 28 天）
  ──────────────────────────────────────────

  序章：适应期（第 1-3 天）
    基调：平静、教学
    · Day 1: AVA 介绍系统，一切正常
    · Day 2: 第一次独立操作，数据正常
    · Day 3: 继续平静。某个读数有微小偏移

  第一章：初兆（第 4-7 天）
    基调：微妙的不安
    · 磁场读数出现无法解释的脉冲
    · 总部回复越来越敷衍
    · 无线电上偶尔收到不在记录中的信号
    · AVA 提到"前几任操作员的平均任期是 14 天"
    · 文件系统中发现一个加密目录

  第二章：暗涌（第 8-14 天）
    基调：紧张、发现
    · 环境异常频率上升
    · 收到标记 [CLASSIFIED] 的误发邮件
    · 无线电信号中包含坐标和日期
    · 解密目录后发现前任操作员的日志
    · AVA 行为出现微妙的不一致

  第三章：真相（第 15-21 天）
    基调：揭示、抉择
    · 发现"气象站"的真实用途
    · 总部的真实指令与表面指令矛盾
    · 必须在"服从"和"质疑"之间做出选择

  终章：结局（第 22-28 天）
    四个结局方向：
    A. 服从者：从不质疑，被调离（不知真相）
    B. 发现者：发现部分真相但选择沉默
    C. 揭露者：发现全部真相并对外传播（高风险）
    D. 理解者：发现全部真相并理解接受（最完整体验）

  结局由 信息发现程度 + 关键对话选择 + 隐藏任务完成度 决定。


  角色阵容
  ──────────────────────────────────────────

  ┌──────────┬──────────────┬───────────────────────────┐
  │  代号    │  身份         │  叙事功能                │
  ├──────────┼──────────────┼───────────────────────────┤
  │  AVA     │  AI 联络员   │  导师/同伴/可能的威胁     │
  │  HQ      │  总部管控    │  权威/信息源/可能的谎言    │
  │  前任    │  前操作员    │  "幽灵"角色/文件中的声音 │
  │  研究员  │  Site 科学家 │  知情者/盟友/关键信息      │
  │  ???     │  未知信号源  │  悬念/恐惧/超自然要素      │
  └──────────┴──────────────┴───────────────────────────┘

  出场节奏：
  Day 1-3:    只有 AVA
  Day 4-7:    AVA + 总部 HQ（邮件/偶尔通讯）+ 前任日志
  Day 8-14:   以上 + 研究员（开始联络）+ 未知信号
  Day 15+:    所有角色 + 关系变化

四、叙事通道总览
================================================================

  SCRT-Reader 有五种讲故事的方式：

  ┌──────────────┬────────────────────────────────┐
  │  通道        │  特点和适用场景                │
  ├──────────────┼────────────────────────────────┤
  │  通讯对话    │  即时、情感化、角色关系导向     │
  │  (Comm)      │  → 揭示角色性格、传递情感      │
  ├──────────────┼────────────────────────────────┤
  │  邮件        │  正式、可延迟、有层次           │
  │  (Mail)      │  → 总部指令、背景设定、伏笔    │
  ├──────────────┼────────────────────────────────┤
  │  文件系统    │  深度、需主动发掘               │
  │  (Files)     │  → 机密档案、日志、隐藏线索    │
  ├──────────────┼────────────────────────────────┤
  │  环境数据    │  渐进、非文字、需要观察力       │
  │  (Env)       │  → 制造不安感、"自己发现"      │
  ├──────────────┼────────────────────────────────┤
  │  无线电信号  │  神秘、碎片化、需要破译         │
  │  (Radio)     │  → 悬念、恐惧氛围、超自然暗示  │
  └──────────────┴────────────────────────────────┘

  通道协同叙事示例（"发现前任操作员失踪真相"）：

  Day  6:  [邮件]    总部发来前任的"调离报告"——看起来很正常
  Day  7:  [文件]    发现前任日志，最后一篇日期中断
  Day  8:  [数据]    前任最后值班那天的环境数据出现极端异常
  Day  9:  [通讯]    AVA 说"前任因个人原因调离"——语气不对
  Day 10:  [无线电]  在废弃频率上收到一段含糊的求救信号
  Day 11:  [邮件]    研究员发来加密邮件："别相信调离报告"
  Day 12:  [通讯]    玩家质问 AVA → AVA 回答出现矛盾
  Day 13:  [文件]    用密码解锁深层目录 → 发现真正的报告


================================================================
五、故事包（.scp）结构
================================================================

  .scp 文件是一个 ZIP 压缩包（只需把 .zip 改名为 .scp）。
  放入游戏的 vdisc/ 目录即可加载。

  文件结构：

  my_story.scp (ZIP)
  ├── manifest.json          故事配置清单（必需）
  ├── files/                 虚拟文件系统内容
  │   ├── docs/
  │   │   └── report.txt     文档（支持 CRT-ML 标记）
  │   └── classified/
  │       └── secret.txt
  ├── mail/                  邮件内容
  │   └── hq_update_01.txt
  ├── radio/                 无线电信号
  │   ├── signals.cfg        信号定义
  │   └── morse_msg.txt      摩斯码内容
  ├── images/                图片素材
  │   └── character/
  │       └── researcher.png
  └── audio/                 音效文件
      └── ambient_loop.ogg

  manifest.json 是核心，它定义了整个故事的所有内容。
  以下各章节会详细介绍 manifest.json 的每个部分。

  manifest.json 的顶级段落：

  {
      "story":            故事基本信息（标题、描述、版本）
      "daily_dialogues":  每日对话触发配置
      "comm_characters":  角色定义
      "comm_dialogues":   对话脚本
      "triggers":         触发器（条件→动作）
      "effects":          自定义效果序列
      "radio_signals":    无线电信号配置
      "filesystem":       虚拟文件系统结构
      "passwords":        密码表
      "phonebook":        拨号号码簿
  }

  文本文件编码：优先使用 UTF-8。系统会自动检测 GBK 编码并转换。


================================================================
六、对话系统详解
================================================================

  对话系统是最主要的叙事手段。

  6.1 角色定义（comm_characters）
  ──────────────────────────────────────────

  在 manifest.json 中定义角色：

  "comm_characters": {
      "ava": {
          "id": "ava",
          "name": "AVA",
          "title": "AI-联络员",
          "portrait": "/images/character/ava.png",
          "voice": {
              "tone": "sine",
              "base_pitch": 0.85,
              "pitch_variance": 0.05,
              "speed": "normal"
          }
      },
      "hq_control": {
          "id": "hq_control",
          "name": "总部管控",
          "title": "HQ-CONTROL",
          "voice": {
              "tone": "square",
              "base_pitch": 0.7,
              "pitch_variance": 0.05,
              "speed": "normal"
          }
      }
  }

  voice 参数说明：

  ┌──────────────────┬───────────────────────────────────┐
  │  参数            │  说明                             │
  ├──────────────────┼───────────────────────────────────┤
  │  tone            │  语音波形                         │
  │                  │  "sine"     柔和（适合人类角色）  │
  │                  │  "square"   机械（适合AI/机器）   │
  │                  │  "triangle" 中性                  │
  │                  │  "sawtooth" 粗糙（适合神秘角色）  │
  ├──────────────────┼───────────────────────────────────┤
  │  base_pitch      │  基础音高（0.0-2.0）              │
  │                  │  越低声音越沉                     │
  ├──────────────────┼───────────────────────────────────┤
  │  pitch_variance  │  音高随机变化幅度                 │
  │                  │  越大声音越不稳定                 │
  ├──────────────────┼───────────────────────────────────┤
  │  speed           │  语速                             │
  │                  │  "slow" / "normal" / "fast"       │
  └──────────────────┴───────────────────────────────────┘

  其他可选字段：
  · portrait: 角色头像图片路径（从 .scp 包内虚拟文件系统加载）


  6.2 对话脚本（comm_dialogues）
  ──────────────────────────────────────────

  "comm_dialogues": {
      "day1_briefing": {
          "title": "第一天 — 到岗报告",
          "description": "新操作员到岗的欢迎通讯",
          "callable": false,
          "repeatable": false,
          "lines": [
              {
                  "character": "ava",
                  "text": "操作员，欢迎抵达 OB-7K 观测站。",
                  "speed": 30
              },
              {
                  "character": "ava",
                  "text": "请输入 [color=#ffaa00]env scan[/color] 执行检测。",
                  "speed": 28,
                  "action": "glitch"
              }
          ]
      }
  }

  对话属性：

  ┌──────────────┬───────────────────────────────────────┐
  │  属性        │  说明                                 │
  ├──────────────┼───────────────────────────────────────┤
  │  title       │  对话标题（显示在通讯界面顶部）       │
  │  description │  描述（可选，在拨号列表中显示）       │
  │  callable    │  true = 玩家可以主动拨号发起          │
  │              │  false = 只能由系统自动触发            │
  │  repeatable  │  true = 每次条件满足都会播放          │
  │              │  false = 只播放一次                    │
  └──────────────┴───────────────────────────────────────┘

  每句台词（line）的属性：

  ┌──────────────┬───────────────────────────────────────┐
  │  属性        │  说明                                 │
  ├──────────────┼───────────────────────────────────────┤
  │  character   │  说话角色的 ID（必须已定义）          │
  │  text        │  台词文本，支持 BBCode 颜色标记       │
  │  speed       │  打字速度（数字越小越快，通常 26-35） │
  │  action      │  屏幕效果，如 "glitch"（可选）        │
  │  auto_next   │  自动推进延迟秒数，如 0.5（可选）     │
  │  condition   │  等待条件（可选，见下方说明）         │
  └──────────────┴───────────────────────────────────────┘

  台词文本中的颜色标记：
  · [color=#ffaa00]橙黄色文字[/color]  — 用于命令提示
  · [color=#ff6666]红色文字[/color]    — 用于警告
  · [color=#66ff66]绿色文字[/color]    — 用于系统信息


  6.3 对话中的等待条件
  ──────────────────────────────────────────

  对话可以暂停，等待玩家完成某个操作后再继续：

  {
      "character": "ava",
      "text": "现在请输入 env scan。",
      "condition": "command:env scan"
  }

  可用的等待条件：

  ┌──────────────────────────────────┬──────────────────────────┐
  │  条件                           │  说明                    │
  ├──────────────────────────────────┼──────────────────────────┤
  │  "condition": "command:命令名"  │  等待玩家执行指定命令    │
  │  "condition": "choice:选择ID"   │  弹出选项让玩家选择      │
  │  "condition": "open_file:路径"  │  等待玩家打开指定文件    │
  │  "condition": "enter_dir:路径"  │  等待玩家进入指定目录    │
  │  "condition": "timer:5.0"       │  等待 5 秒后自动继续     │
  └──────────────────────────────────┴──────────────────────────┘


  6.4 选择分支
  ──────────────────────────────────────────

  使用 "condition": "choice:选择ID" 可以弹出选项：

  "day5_question": {
      "lines": [
          {
              "character": "ava",
              "text": "你想了解什么？",
              "condition": "choice:day5_q1"
          },
          {"character": "ava", "text": "1. 问关于前任的事"},
          {"character": "ava", "text": "2. 问关于异常数据"},
          {"character": "ava", "text": "3. 没什么，再见"}
      ]
  },
  "day5_question_a1": { ... },  // 选择 1 的后续对话
  "day5_question_a2": { ... },  // 选择 2 的后续对话
  "day5_question_a3": { ... }   // 选择 3 的后续对话

  命名规则：选项分支的对话 ID = 基础ID + "_a1"/"_a2"/"_a3"


  6.5 对话的前置条件
  ──────────────────────────────────────────

  对话可以设置前置条件，只有满足条件才会触发：

  "secret_dialogue": {
      "title": "隐藏对话",
      "callable": false,
      "repeatable": false,
      "requires_choice": {
          "day5_q1": "investigate"
      },
      "requires_flag": {
          "found_secret_file": true
      },
      "requires_mail": "classified_leak",
      "requires_command": "env scan",
      "lines": [ ... ]
  }

  · requires_choice:  要求玩家做过某个选择
  · requires_flag:    要求某个剧情标记已设置
  · requires_mail:    要求玩家已阅读某封邮件
  · requires_command: 要求玩家已执行某个命令


  6.6 来电对话与呼叫模式
  ──────────────────────────────────────────

  在对话数据中设置 "trigger": "incoming_call" 会触发来电。
  通过 "call_mode" 字段控制来电行为：

  ┌──────────────┬───────────────────────────────────────┐
  │  call_mode   │  行为说明                             │
  ├──────────────┼───────────────────────────────────────┤
  │  "silent"    │  静默接入，无铃声，直接开始对话       │
  │  "forced"    │  播放铃声后自动接通，玩家无法拒绝     │
  │  "answerable"│  播放铃声后等待玩家操作：              │
  │              │  comm answer 接听 / comm reject 拒绝  │
  └──────────────┴───────────────────────────────────────┘

  默认值：incoming_call 触发器默认使用 "answerable" 模式。

  示例（强制来电）：

  "emergency_call": {
      "trigger": "incoming_call",
      "call_mode": "forced",
      "lines": [
          { "character": "hq_control", "text": "紧急通讯！" }
      ]
  }

  示例（可拒绝来电，带拒绝后果）：

  "optional_call": {
      "trigger": "incoming_call",
      "call_mode": "answerable",
      "reject_consequence": "comm:miss_call_dialogue",
      "lines": [
          { "character": "ava", "text": "操作员，有一条消息。" }
      ]
  }

  reject_consequence 可以是任何触发器动作字符串。


  6.7 视频通讯 / 大图模式（Meeting Mode）
  ──────────────────────────────────────────

  大图模式让角色以 galgame 风格全身像显示在屏幕上。

  在对话台词中设置 display_mode 和 meeting_slot：

  {
      "character": "ava",
      "text": "切换到视频通讯模式。",
      "display_mode": "meeting",
      "meeting_slot": "center",
      "char_anim": "slide_in_center"
  }

  位置选项（meeting_slot）：
  · "left"   — 画面左侧 (x=15%)
  · "center" — 画面中央 (x=50%)
  · "right"  — 画面右侧 (x=85%)

  入场/退场动画（char_anim）：
  · "slide_in_left"  / "slide_out_left"
  · "slide_in_right" / "slide_out_right"
  · "slide_in_center"
  · "fade_in" / "fade_out"
  · "shake"

  多角色同屏：
  · 不同角色分配不同 slot，系统自动管理显示层级
  · 当前说话角色自动高亮（全亮度），其他角色降暗
  · 同一 slot 多角色时自动水平错开，避免重叠

  将对话标记为视频频道（可通过 comm video 列表选择）：

  "ava_meeting": {
      "title": "AVA - 视频通讯",
      "callable": true,
      "repeatable": true,
      "video_call": true,
      "video_number": "1001-0001",
      "lines": [ ... ]
  }

  · video_call: true — 标记为视频通讯频道
  · video_number — 对应的拨号号码，玩家可用 dial 或 comm video 呼叫

  玩家使用方式：
  · comm              — 显示通讯状态
  · comm answer       — 接听来电
  · comm reject       — 拒绝来电
  · comm video        — 显示所有视频频道列表
  · comm video <号码> — 通过拨号系统呼叫指定频道
  · comm phonebook    — 显示通讯录
  · comm history      — 查看通讯历史记录
  · dial <号码>       — 直接拨号呼叫


  6.8 演示模式（Presentation Mode）
  ──────────────────────────────────────────

  在 meeting 模式基础上，可以同时显示幻灯片/PPT 图片：

  {
      "character": "ava",
      "text": "请看这份数据报告——",
      "display_mode": "presentation",
      "meeting_slot": "left",
      "slide_image": "images/slide1.png",
      "slide_position": [0.55, 0.1],
      "slide_size": [0.4, 0.5],
      "slide_fit": "contain",
      "slide_align": "center",
      "slide_transition": "fade"
  }

  字段说明：

  · slide_image: 幻灯片图片路径（从 .scp 包或 res:// 加载）
  · slide_position: [x, y] 归一化坐标 (0.0-1.0)，默认 [0.55, 0.1]
  · slide_size: [w, h] 归一化尺寸 (0.0-1.0)，默认 [0.4, 0.5]
  · slide_area: [x, y, w, h] 展示区域，覆盖 position+size（可选）
  · slide_fit: 图片适配模式（可选）
    "contain" — 保持比例完整显示（默认）
    "cover"   — 保持比例填满区域（可能裁剪）
    "stretch" — 拉伸填满区域（可能变形）
    "actual"  — 原始尺寸居中显示
  · slide_align: 图片在展示区域内的对齐方式（可选）
    "center"（默认） / "top_left" / "top_center" / "top_right"
    "center_left" / "center_right"
    "bottom_left" / "bottom_center" / "bottom_right"
  · slide_transition: 过渡动画
    "fade" / "instant" / "slide_left" / "slide_right"

  隐藏幻灯片：

  {
      "character": "ava",
      "text": "报告展示完毕。",
      "slide_hide": true
  }

  或指定退出动画：

  { "slide_hide": "slide_left" }

七、每日对话配置
================================================================

  每日对话配置决定"哪一天的什么时刻触发哪些对话"。

  7.1 配置格式
  ──────────────────────────────────────────

  在 manifest.json 的 "daily_dialogues" 段中配置：

  "daily_dialogues": {
      "1": {
          "on_start": ["day1_briefing"],
          "on_scan_complete": ["day1_scan_done"],
          "on_anomaly": []
      },
      "2": {
          "on_start": ["day2_morning"],
          "on_scan_complete": [],
          "on_anomaly": ["day2_anomaly_reaction"]
      },
      "default": {
          "on_start": ["daily_routine_greeting"],
          "on_scan_complete": [],
          "on_anomaly": []
      }
  }

  · 键名 = 天数编号的字符串（"1"、"2"、"3"...）
  · "default" = 没有特定配置的天数使用此默认
  · 每个时机的值 = 对话 ID 数组（按顺序触发）


  7.2 五种触发时机
  ──────────────────────────────────────────

  ┌──────────────────┬───────────────────────────────────┐
  │  触发时机        │  说明                             │
  ├──────────────────┼───────────────────────────────────┤
  │  on_start        │  每天登录后自动触发               │
  │                  │  适合：晨间问候、每日简报          │
  ├──────────────────┼───────────────────────────────────┤
  │  on_scan_complete│  env scan 完成后触发              │
  │                  │  适合：对扫描结果的反应            │
  ├──────────────────┼───────────────────────────────────┤
  │  on_anomaly      │  扫描检测到异常数据时触发         │
  │                  │  适合：紧急反应                    │
  ├──────────────────┼───────────────────────────────────┤
  │  on_mail_read    │  玩家阅读特定邮件后触发           │
  │                  │  需配合 requires_mail 使用         │
  ├──────────────────┼───────────────────────────────────┤
  │  on_command      │  玩家执行特定命令后触发           │
  │                  │  需配合 requires_command 使用      │
  └──────────────────┴───────────────────────────────────┘


  7.3 扩展对话文件
  ──────────────────────────────────────────

  对话数据可以拆分到多个文件中。系统会自动扫描
  dialogues/ 目录下的所有 .json 文件并合并。

  data/main/
  ├── manifest.json          主文件（Day 1-3）
  └── dialogues/
      └── day_04_07.json     Day 4-7 的扩展对话

  扩展文件格式与主文件完全相同：

  {
      "daily_dialogues": {
          "4": {
              "on_start": ["day4_morning"],
              "on_anomaly": ["day4_anomaly"]
          }
      },
      "comm_dialogues": {
          "day4_morning": {
              "title": "第四天 — 总部回复",
              "callable": false,
              "repeatable": false,
              "lines": [
                  {
                      "character": "ava",
                      "text": "总部终于回复了。",
                      "speed": 30
                  }
              ]
          }
      }
  }

八、邮件系统
================================================================

  邮件是重要的叙事通道，适合传递正式信息和伏笔。

  8.1 邮件文件格式
  ──────────────────────────────────────────

  邮件存放在 mail/ 目录中，使用文本文件 + 头部格式：

  文件示例：mail/hq_update_01.txt

  ---
  title: 每周例行更新
  template: email
  mail_priority: normal
  ---
  From: 总部管控 <hq@site-control.org>
  Subject: 第一周工作确认
  Date: Day 3

  操作员，

  确认收到你前三天的所有监测报告。
  数据质量合格，请继续保持。

  如遇异常情况，请及时上报。

  ——总部管控


  头部字段（--- 之间的部分）：

  ┌──────────────────┬───────────────────────────────────┐
  │  字段            │  说明                             │
  ├──────────────────┼───────────────────────────────────┤
  │  title           │  邮件标题（显示在收件箱列表）     │
  │  template        │  显示模板：                       │
  │                  │  "email"（标准邮件，默认）        │
  │                  │  "article"（文章格式）            │
  │                  │  "chat"（聊天记录格式）           │
  │                  │  "two_page_reader"（双页阅读器）  │
  │  mail_priority   │  优先级：                         │
  │                  │  "normal" / "high" / "classified" │
  │  mail_delay      │  投递延迟（毫秒）                 │
  │                  │  模拟异步通信                     │
  └──────────────────┴───────────────────────────────────┘


  8.2 通过触发器投递邮件
  ──────────────────────────────────────────

  邮件需要通过触发器投递，不会自动出现：

  "triggers": {
      "/docs": {
          "on_enter": "new_mail:hq_update_01"
      }
  }

  延迟投递：
  "on_enter": "delay:5000:new_mail:hq_update_01"
  → 进入目录 5 秒后才投递邮件

  持久邮件（不随故事包卸载消失）：
  "on_enter": "new_mail:hq_update_01:persistent"

  "filesystem": {

  │  participants    │  聊天参与者（chat 模板用）        │
  └──────────────────┴───────────────────────────────────┘

十、触发器系统
================================================================

  触发器 = 玩家做了某事 → 自动执行某个反应。

  10.1 在 manifest.json 中定义
  ──────────────────────────────────────────

  "triggers": {
      "/docs": {
          "on_enter": "text:欢迎访问文档库"
      },
      "/classified": {
          "on_first_enter": "glitch:0.8;comm:ava_warning"
      }
  }

  键 = 目录路径，值 = 触发条件和动作的字典。


  10.2 触发条件
  ──────────────────────────────────────────

  ┌──────────────────────────────┬──────────────────────────┐
  │  条件                       │  说明                    │
  ├──────────────────────────────┼──────────────────────────┤
  │  on_enter                   │  进入目录（可重复）      │
  │  on_first_enter             │  首次进入（一次性）      │
  │  on_open_file:文件名        │  打开文件（一次性）      │
  │  on_read_complete:文件路径  │  阅读完毕（一次性）      │
  │  on_level_reach:等级数      │  权限到达（一次性）      │
  │  on_command:命令名          │  执行命令（可重复）      │
  │  on_idle:秒数               │  空闲N秒（每次一次）     │
  └──────────────────────────────┴──────────────────────────┘

  修饰符：加 .once 变为一次性，加 .repeat 变为可重复
  · on_enter.once = "..."       → 只在第一次进入时触发
  · on_command:scan.once = "..." → 只触发一次


  10.3 触发动作
  ──────────────────────────────────────────

  ┌──────────────────────────┬──────────────────────────────┐
  │  动作                   │  说明                        │
  ├──────────────────────────┼──────────────────────────────┤
  │  new_mail:邮件ID        │  投递邮件                    │
  │  level_up:等级          │  提升权限                    │
  │  text:消息内容          │  终端输出文字                │
  │  sound:音效路径         │  播放音效                    │
  │  redirect:/目标路径     │  自动切换目录                │
  │  comm:对话ID            │  触发通讯对话                │
  │  glitch:强度或预设      │  屏幕故障                    │
  │  shake:强度             │  屏幕震动                    │
  │  tear:强度              │  画面撕裂                    │
  │  noise_burst:强度       │  噪点爆发                    │
  │  screen_off:毫秒        │  屏幕关闭                    │
  │  reboot                 │  终端重启                    │
  │  lock_folder:/路径      │  锁定目录                    │
  │  unlock_folder:/路径    │  解锁目录                    │
  │  color_scheme:主题名    │  切换配色                    │
  │  play_effect:效果ID     │  播放效果序列                │
  │  preset_effect:预设名   │  播放内置预设                │
  │  delay:毫秒:动作        │  延迟执行                    │
  └──────────────────────────┴──────────────────────────────┘

  多个动作用分号（;）分隔：
  "on_first_enter": "glitch:0.5;text:检测到访问;comm:ava_warning"

  延迟组合：
  "on_open_file:secret.txt": "glitch:heavy;delay:3000:new_mail:hq_alert"
  → 先触发故障效果，3 秒后投递邮件

  text 动作支持变量替换：
  · {username}  → 当前用户名
  · {level}     → 当前权限等级
  · {path}      → 当前目录路径


  10.4 使用示例
  ──────────────────────────────────────────

  示例 1：首次进入加密目录
  "triggers": {
      "/classified": {
          "on_first_enter": "glitch:heavy;shake:0.02:800;comm:ava_warning"
      }
  }

  示例 2：读完报告后收到邮件并提权
  "triggers": {
      "/docs": {
          "on_read_complete:reports/incident_07.txt":
              "delay:2000:new_mail:hq_upgrade;delay:3000:level_up:3"
      }
  }

  示例 3：空闲 60 秒后角色联络
  "triggers": {
      "/": {
          "on_idle:60": "comm:ava_idle_check"
      }
  }

十一、文本标记语法（CRT-ML）
================================================================

  CRT-ML 是文件内容中使用的自定义标记语言。

  11.1 标题和排版
  ──────────────────────────────────────────

  # 一级标题               大标题（加框、加粗、主题色）
  ## 二级标题              中标题（下划线、加粗）
  ### 三级标题             小标题（加粗、主题色）

  ---                      分割线（三个或更多短横线）
  ===                      分割线（三个或更多等号）

  ---PAGE---               分页标记（翻页文档的分页点）

  > 这是引用文本           引用块（缩进显示）

  | 列A | 列B | 列C |     表格
  |-----|-----|-----|
  | 数据 | 数据 | 数据 |


  11.2 文字样式
  ──────────────────────────────────────────

  **粗体文字**             Markdown 风格粗体
  *斜体文字*               Markdown 风格斜体
  ~~删除线~~               删除线
  `内联代码`               等宽代码

  {b}粗体{/b}              标记风格粗体
  {i}斜体{/i}              标记风格斜体
  {u}下划线{/u}            下划线
  {s}删除线{/s}            标记风格删除线

  {color:red}红色{/color}   着色（支持颜色名或 #RRGGBB）
  可用颜色名：primary, error, warning, muted,
              success, info, secondary, dim

  [redacted]               涂黑遮蔽标记 [REDACTED]
  [DATA EXPUNGED]          数据删除标记
  [CLASSIFIED]             机密标记
  [ACCESS DENIED]          访问拒绝标记

  ||剧透文字||             黑块遮盖（点击可显示）

  @@原始文本@@             不解析的原始文本块


  11.3 打字效果控制
  ──────────────────────────────────────────

  {speed=30}文字{/speed}   设置打字速度（数字越大越慢）
  {delay=2000}             暂停 2 秒
  {pause=1000}             暂停 1 秒
  {clear}                  清空屏幕
  {noskip}文字{/noskip}    不可跳过的段落


  11.4 文字动画
  ──────────────────────────────────────────

  {shake}文字{/shake}      文字抖动
  {wave}文字{/wave}        文字波浪
  {rainbow}文字{/rainbow}  彩虹色
  {fade}文字{/fade}        渐显效果
  {center}文字{/center}    居中
  {right}文字{/right}      右对齐


  11.5 CRT 屏幕效果标记（内联在文本中）
  ──────────────────────────────────────────

  这些标记嵌入文件正文中，打字机显示到该位置时
  自动触发屏幕效果：

  {glitch}                 屏幕故障（默认强度 0.5）
  {glitch=0.8}             指定强度
  {/glitch}                结束

  {screen_shake}           屏幕震动
  {screen_shake=0.03}      指定强度
  {/screen_shake}          结束

  {tear}                   画面撕裂
  {tear=0.1}               指定强度
  {/tear}                  结束

  {noise}                  噪点爆发
  {noise=0.6}              指定强度
  {/noise}                 结束

  {effect=效果ID}          触发自定义效果序列
  {preset=预设名}          触发内置预设


  11.6 多媒体内联
  ──────────────────────────────────────────

  ![image](path/photo.png)        内联图片
  ![image|32](path/photo.png)     指定宽度（字符单位）
  ![audio](path/signal.ogg)       内联音频播放器
  ![video](path/footage.ogv)      视频播放器

十二、屏幕特效
================================================================

  屏幕特效是 CRT 终端氛围的核心工具。

  12.1 特效列表
  ──────────────────────────────────────────

  ┌──────────────┬───────────┬─────────────────────────┐
  │  特效名      │  参数范围 │  视觉效果               │
  ├──────────────┼───────────┼─────────────────────────┤
  │  glitch      │ 0.1-2.0   │  CRT 信号故障/花屏     │
  │              │ 或预设名  │  预设: subtle/moderate  │
  │              │           │  heavy/chaos            │
  ├──────────────┼───────────┼─────────────────────────┤
  │  shake       │ 0.001-0.1 │  屏幕震动               │
  ├──────────────┼───────────┼─────────────────────────┤
  │  tear        │ 0.01-0.15 │  画面水平撕裂           │
  ├──────────────┼───────────┼─────────────────────────┤
  │  noise_burst │ 0.1-1.0   │  短暂雪花噪点           │
  ├──────────────┼───────────┼─────────────────────────┤
  │  screen_off  │ 毫秒数    │  屏幕关闭一段时间       │
  ├──────────────┼───────────┼─────────────────────────┤
  │  reboot      │ 无参数    │  完整重启序列           │
  ├──────────────┼───────────┼─────────────────────────┤
  │  brightness  │ 0.0-2.0   │  亮度渐变               │
  ├──────────────┼───────────┼─────────────────────────┤
  │  chromatic   │ 2.0-4.5   │  色差分离               │
  ├──────────────┼───────────┼─────────────────────────┤
  │  flicker     │ 0.0-1.0   │  屏幕闪烁               │
  ├──────────────┼───────────┼─────────────────────────┤
  │  blackout    │ 秒数      │  全黑                   │
  ├──────────────┼───────────┼─────────────────────────┤
  │  shutdown    │ 秒数      │  CRT 关机动画           │
  ├──────────────┼───────────┼─────────────────────────┤
  │  boot        │ 秒数      │  CRT 开机动画           │
  └──────────────┴───────────┴─────────────────────────┘


  12.2 自定义效果序列
  ──────────────────────────────────────────

  在 manifest.json 中定义复合效果：

  "effects": {
      "jumpscare_01": {
          "steps": [
              {"time": 0.0, "action": "glitch",
               "params": {"intensity": 0.8, "duration": 1.5}},
              {"time": 0.0, "action": "shake",
               "params": {"intensity": 0.02, "duration": 1.0}},
              {"time": 0.5, "action": "noise_burst",
               "params": {"intensity": 0.9, "duration": 0.4}},
              {"time": 1.5, "action": "blackout",
               "params": {"duration": 1.0}},
              {"time": 3.0, "action": "reboot"}
          ]
      }
  }

  · time: 从效果开始算起的秒数
  · action: 效果类型（见上表）
  · params: 参数字典

  通过触发器使用：play_effect:jumpscare_01
  通过文本内联：{effect=jumpscare_01}


  12.3 内置预设
  ──────────────────────────────────────────

  系统提供四种内置预设效果：

  · unease:    轻微故障+色差+闪烁（暗示不安）
  · disturb:   中等故障+震动+噪点+撕裂（异常反应）
  · jumpscare: 强烈故障+震动+噪点+色差+黑屏（恐怖瞬间）
  · system_crash: 渐进故障→错误文字→噪点→重启

  使用方式：
  触发器：preset_effect:unease:2000
  文本内联：{preset=unease}


  12.4 使用场景建议
  ──────────────────────────────────────────

  · 日常小故障：  glitch:subtle
  · 异常反应：    glitch:0.5;shake:0.01
  · 重要发现：    glitch:heavy;tear:0.08:800
  · 恐怖时刻：    screen_off:3000;delay:3500:noise_burst:1.0
  · 关键转折：    reboot

十三、无线电系统
================================================================

  无线电接收器用于"神秘碎片化叙事"。
  玩家打开无线电界面，调整频率和天线方向来收听信号。

  13.1 信号类型
  ──────────────────────────────────────────

  ┌──────────┬────────────────────────────────────┐
  │  类型    │  说明                              │
  ├──────────┼────────────────────────────────────┤
  │  morse   │  摩斯码：滴答声编码的文字信息      │
  │          │  需要玩家解码或等待系统自动翻译    │
  ├──────────┼────────────────────────────────────┤
  │  sstv    │  慢扫描电视：传输图片              │
  │          │  图像缓慢"扫描"显示，带特征音    │
  ├──────────┼────────────────────────────────────┤
  │  audio   │  音频电台：环境音/语音/加密通信    │
  │          │  像收听电台一样                    │
  └──────────┴────────────────────────────────────┘

  13.2 频段
  ──────────────────────────────────────────

  · LF:  0.1-0.5 MHz（长波）
  · HF:  1.8-30 MHz（短波，最常用）
  · VHF: 30-300 MHz（超短波）
  · UHF: 300-3000 MHz（特高频）

  13.3 配置信号
  ──────────────────────────────────────────

  在 manifest.json 中：

  "radio_signals": [
      {
          "id": "unknown_signal_01",
          "type": "morse",
          "frequency": 14.225,
          "band": "HF",
          "azimuth": 145,
          "elevation": 20,
          "tolerance_freq": 0.04,
          "tolerance_dir": 25,
          "content_file": "/radio/msg01.txt",
          "loop": false,
          "speed_wpm": 12,
          "label": "未知信号"
      }
  ]

  或在 radio/signals.cfg 中用 INI 格式：

  [unknown_signal_01]
  type = morse
  frequency = 14.225
  band = HF
  azimuth = 145
  elevation = 20
  content_file = radio/msg01.txt
  speed_wpm = 12
  label = 未知信号

  参数说明：

  ┌──────────────────┬───────────────────────────────────┐
  │  参数            │  说明                             │
  ├──────────────────┼───────────────────────────────────┤
  │  frequency       │  信号频率（MHz）                  │
  │  band            │  频段（LF/HF/VHF/UHF）           │
  │  azimuth         │  天线方位角（0-359度）            │
  │  elevation       │  天线仰角（0-90度）               │
  │  tolerance_freq  │  频率容差（±MHz）                 │
  │  tolerance_dir   │  角度容差（±度）                  │
  │  content_file    │  内容文件路径                     │
  │  speed_wpm       │  摩斯码速度（字/分钟）            │
  │  loop            │  是否循环播放                     │
  │  label           │  信号名称（显示在界面上）         │
  │  hidden          │  true = 不在雷达上显示标记        │
  │  ephemeral       │  true = 被发现后消失              │
  │  discovered_flag │  发现时设置的剧情标记名           │
  └──────────────────┴───────────────────────────────────┘

  信号质量由三个因素决定：
  频率匹配度 × 方位角匹配度 × 仰角匹配度 = 信号质量 (0-1)

十四、剧情分支与存档
================================================================

  14.1 存档系统
  ──────────────────────────────────────────

  主线剧情进度保存在独立文件中：
  saves/{用户名}/story_progress.json

  存档内容：
  · story_day:           当前天数
  · completed_dialogues: 已完成的对话列表
  · story_choices:       玩家的选择记录 {选择ID: 选项值}
  · story_flags:         剧情标记 {标记名: 值}

  存档独立于磁盘/故事包存档，主线进度不受影响。


  14.2 选择记录
  ──────────────────────────────────────────

  当对话中出现选择时，系统自动记录：
  · 选择ID → 玩家选的选项值

  后续对话通过 requires_choice 检查之前的选择：

  "day10_trust": {
      "requires_choice": {
          "day8_decision": "trust_ava"
      },
      "lines": [
          {"character": "ava", "text": "谢谢你信任我。"}
      ]
  },
  "day10_doubt": {
      "requires_choice": {
          "day8_decision": "doubt_ava"
      },
      "lines": [
          {"character": "ava", "text": "我知道你对我有疑虑……"}
      ]
  }


  14.3 剧情标记
  ──────────────────────────────────────────

  标记（Flag）是通用变量，追踪玩家的发现和行为：

  · 例如 "found_secret_file" = true
  · 例如 "trust_level" = "high"

  对话通过 requires_flag 检查：

  "hidden_dialogue": {
      "requires_flag": {
          "found_secret_file": true,
          "trust_level": "high"
      },
      "lines": [ ... ]
  }

  只有同时满足所有条件的对话才会触发。

  标记可以通过触发器中的 on_read_complete 等条件
  配合 comm 动作来设置（在对话中调用系统的
  set_flag 接口）。

十五、自定义加载画面
================================================================

  故事包可以通过在根目录放置 loading_screen.json 来完全
  替换默认的磁盘加载动画。该文件使用关键帧时间轴引擎，
  和开机动画（boot_config.json）采用相同的设计模式。

  15.1 基本结构
  ──────────────────────────────────────────

  {
      "skippable": true,
      "total_duration": 8.0,
      "keyframes": [
          { "time": 0.0, "action": "clear" },
          { "time": 0.0, "action": "text", "params": {
              "content": "正在加载...", "color": "muted" } },
          { "time": 1.0, "action": "disc_title" },
          { "time": 1.5, "action": "disc_info" },
          { "time": 2.0, "action": "separator" },
          { "time": 2.5, "action": "progress_bar", "params": {
              "duration": 4.0 } },
          { "time": 7.0, "action": "text", "params": {
              "content": "加载完成。", "color": "success" } },
          { "time": 8.0, "action": "complete" }
      ]
  }

  顶层字段：
    · skippable      是否允许按任意键跳过（默认 true）
    · total_duration  动画总时长（秒）
    · audio           背景音乐的虚拟文件路径（可选）
    · audio_volume    音乐音量 0.0~1.0（默认 0.6）
    · keyframes       关键帧数组，按 time 排序

  15.2 支持的关键帧动作
  ──────────────────────────────────────────

  【文字输出】
    text           终端文字      params: content, color
    text_center    居中文字      params: content, color
    disc_title     磁盘标题框    params: color（可选）
    disc_info      作者/版本/ID  params: color（可选）
    separator      分隔线        params: char, width, color
    ascii_art      ASCII 艺术    params: content, color

  【视觉效果】
    glitch         故障效果      params: intensity, duration
    scanlines      扫描线        params: intensity
    screen_flash   屏幕闪白      params: duration

  【音频】
    beep           蜂鸣音
    sound          播放音效      params: path（虚拟FS路径）
    audio_play     播放背景音乐  params: path（可选）

  【流程控制】
    clear          清屏
    wait           纯等待占位
    progress_bar   进度条        params: duration, label
    complete       结束加载画面

  15.3 颜色名称
  ──────────────────────────────────────────

  在 color 参数中可使用以下名称，会自动匹配当前主题色：
    primary   主色（默认绿色）
    success   成功色
    warning   警告色
    error     错误色
    muted     灰色/次要色

  15.4 变量替换
  ──────────────────────────────────────────

  text 和 text_center 的 content 中可使用以下变量：
    {disc_title}    故事标题
    {disc_author}   作者
    {disc_version}  版本号
    {disc_id}       故事 ID
    {username}      当前登录用户名

  15.5 注意事项
  ──────────────────────────────────────────

  · loading_screen.json 放在 .scp 包的根目录
  · 如果 .scp 有顶层文件夹包裹，放在那个文件夹内即可
  · 加载画面播放期间，终端输入被禁用
  · disc_title、disc_info、progress_bar 等动作的视觉效果
    与默认动画相同——如果想要完全不同的外观，请用 text
    动作自行拼装内容
  · complete 动作是必须的，否则动画在 total_duration+1
    秒后才会超时结束
  · manifest.json 中的 loading_screen 字段已弃用，
    请使用独立的 loading_screen.json 文件


十六、创作工作流总结
================================================================

  15.1 写一天主线剧情的步骤
  ──────────────────────────────────────────

  1. 决定叙事目标
     · 这天要推进什么剧情？
     · 玩家应该发现或感受到什么？
     · 用哪些叙事通道传递信息？

  2. 编写对话脚本
     · 创建 dialogues/day_XX.json
     · 写 comm_dialogues（角色、台词、速度、效果）

  3. 配置每日触发
     · 在 daily_dialogues 中添加该天的配置
     · 决定哪些对话在什么时机触发

  4. 准备文件内容
     · 编写新解锁的文件（用 CRT-ML 标记）

  5. 配置邮件
     · 写邮件文件，设置触发器投递

  6. 设置触发器
     · 根据玩家行为设置反应
     · 串联多个动作创造连锁效果

  7. 调整环境数据（如需要）
     · 配置传感器偏移制造故事性异常


  15.2 写支线故事（.scp 包）的步骤
  ──────────────────────────────────────────

  1. 创建目录，准备 manifest.json
  2. 定义角色 + 编写对话 + 创建文件内容
  3. 配置每日触发、邮件和触发器
  4. 压缩为 .zip → 改名 .scp → 放入 vdisc/ 测试


  15.3 对话模板（可直接复制修改）
  ──────────────────────────────────────────

  简单的一天对话：

  {
      "daily_dialogues": {
          "5": {

              "lines": [
                  {
                      "character": "ava",
                      "text": "早安，操作员。今天天气不错。",
                      "speed": 30
                  },
                  {
                      "character": "ava",
                      "text": "请开始日常检测。",
                      "speed": 28
                  }
              ]
          },
          "day5_result": {
              "title": "第五天 — 扫描完成",
              "callable": false,
              "repeatable": false,
              "lines": [
                  {
                      "character": "ava",
                      "text": "扫描完成。一切正常。",
                      "speed": 30

          }

  带效果的紧张对话：

      "title": "紧急通讯",
      "callable": false,
      "repeatable": false,
      "lines": [
          {
              "character": "ava",
              "text": "操作员——检测到异常信号。",
              "speed": 26,

              "glitch:moderate;text:[SYSTEM] 检测到未授权访问",

  触发条件速查
  ──────────────────────────────────────────
  on_enter              进入目录（可重复）
  on_first_enter        首次进入（一次性）
  on_open_file:名       打开文件（一次性）
  on_read_complete:路径 阅读完毕（一次性）
  on_level_reach:N      权限达到N（一次性）
  on_command:名         执行命令（可重复）
  on_idle:秒            空闲N秒（每次一次）

  触发动作速查
  ──────────────────────────────────────────
  new_mail:ID           投递邮件
  level_up:N            提升权限
  text:内容             终端输出
  sound:路径            播放音效
  redirect:/路径        切换目录
  comm:对话ID           触发对话
  glitch:强度           屏幕故障（预设: subtle/moderate/heavy/chaos）
  shake:强度            屏幕震动
  tear:强度             画面撕裂
  noise_burst:强度      噪点爆发
  screen_off:毫秒       屏幕关闭
  reboot                终端重启
  lock_folder:/路径     锁定目录
  unlock_folder:/路径   解锁目录
  color_scheme:名       切换配色
  play_effect:ID        播放效果序列
  preset_effect:名      播放内置预设（unease/disturb/jumpscare/system_crash）
  delay:毫秒:动作       延迟执行

  每日对话触发时机速查
  ──────────────────────────────────────────
  on_start              登录后
  on_scan_complete      扫描完成后
  on_anomaly            检测到异常
  on_mail_read          阅读邮件后
  on_command            执行命令后

  CRT-ML 标记速查
  ──────────────────────────────────────────
  # / ## / ###           标题

  ---PAGE---             分页
