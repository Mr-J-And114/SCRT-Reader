 SCRT-Reader 监控摄像头系统 — 素材制作与集成指导
==============================================================
 版本: 1.0
 适用于: SCRT-Reader camera_system 模块
 最后更新: 2026-03-04
==============================================================


1. 系统概述
============================================================

监控摄像头系统让玩家通过 `camera` 命令查看站内/站外的 CCTV 画面。
每个摄像头由以下素材层叠组成：

  ┌─────────────────────────────┐
  │  底图 (base_image)          │ ← 摄像头实际拍摄的场景
  │  + 深度图 (depth_map)       │ ← 灰度图，用于伪3D透视效果
  │  + 照明图 (light_image)     │ ← 可选，夜视/红外/聚光灯照明
  │  + 异常图 (anomaly image)   │ ← 可选，异常事件时叠加的画面
  └─────────────────────────────┘
        ↓ 经过 Shader 渲染 ↓
  ┌─────────────────────────────┐
  │  最终画面                    │
  │  = 扫描线 + 噪点 + 暗角     │
  │  + 信号干扰 + 雪花点        │
  │  + 时间戳 HUD              │
  └─────────────────────────────┘

玩家可用方向键平移镜头查看底图的不同区域。


2. 素材规格总览
============================================================

  素材类型      │ 格式     │ 推荐尺寸         │ 必须？
  ─────────────┼──────────┼─────────────────┼───────
  底图          │ PNG/JPG  │ 1920×1080 以上   │ 是
  深度图        │ PNG      │ 与底图相同尺寸   │ 否*
  照明图        │ PNG      │ 与底图相同尺寸   │ 否
  异常图        │ PNG/JPG  │ 与底图相同尺寸   │ 否

  * 深度图不提供时不启用伪3D透视，画面变为纯2D平移。

所有图片必须放在 .scp 包的 data/ 目录下（可分子目录）。
路径在 manifest.json 中以相对于 data/ 根目录的形式配置。


3. 底图 (Base Image) 制作
============================================================

底图是摄像头看到的完整场景。因为玩家只能看到底图的一个
「窗口」（由 viewport_size 控制），所以底图应该比最终显示
尺寸大。

3.1 推荐做法
- 尺寸: 1920×1080 ~ 3840×2160（越大可平移范围越广）
- 风格: 建议使用真实摄像头截图/3D渲染/手绘均可
- 色调: 系统 shader 会自动进行色彩压缩和绿色/灰度偏移，
        所以底图本身可以是正常彩色
- 角度: 典型的安防摄像头视角（固定机位、略俯视或平视）

3.2 底图示例场景
- 走廊监控: 长廊透视，门框/管道细节
- 实验室: 仪器台、储物柜、操作面板
- 室外: 码头、停机坪、围栏、灯塔
- 储藏室: 收容物、标本架、安全门

3.3 注意事项
- 避免纯黑/纯白大面积区域（shader 噪点在极端亮度下效果差）
- 底图中如有文字/标志，注意是否需要翻转（真实摄像头有些镜像）
- 如果需要展示动态内容（如屏幕亮着），直接画在底图上即可


4. 深度图 (Depth Map) 制作
============================================================

深度图用于伪3D透视效果。当玩家平移镜头时，近处物体移动快、
远处物体移动慢，产生视差（parallax）。

4.1 灰度规则
- 白色 (255) = 离镜头最近
- 黑色 (0)   = 离镜头最远

4.2 制作方法

方法A: 手绘（推荐简单场景）
  1. 在底图上新建图层
  2. 用灰色笔刷按物体远近涂色
     - 前景物体（桌子、门框）= 浅灰/白
     - 中景（墙壁、家具）= 中灰
     - 远景（走廊尽头、窗外）= 深灰/黑
  3. 高斯模糊 3-5px 使过渡平滑
  4. 导出为灰度 PNG

方法B: 3D 渲染深度通道
  如果你的底图是 3D 渲染的：
  1. 在 Blender/Unity/UE 中启用 Z-depth 输出
  2. 将深度缓冲导出为图片
  3. 反转亮度（使近白远黑）
  4. 调整对比度使深度范围合理

方法C: AI 深度估计
  使用 Depth Anything / MiDaS / Marigold 等深度估计模型：
  1. 输入底图
  2. 获取深度图输出
  3. 可能需要手动修正明显错误区域

4.3 效果预览
  深度图越精细，镜头平移时的视差感越强。
  粗糙的深度图也完全可用——系统会自动混合。
  完全不提供深度图时，画面退化为纯2D平移（也是合理的）。

4.4 参数调节
  Shader 中深度偏移量由 camera_viewer.gd 内部控制。
  当前默认偏移强度约为深度值 × 0.02，足以产生微妙的视差感。


5. 照明图 (Light Image) 制作
============================================================

照明图配合 light_mode 参数使用，模拟不同的照明环境。

5.1 三种照明模式

  ┌───────────────┬──────────────────────────────────────────┐
  │ light_mode    │ 效果说明                                 │
  ├───────────────┼──────────────────────────────────────────┤
  │ "spotlight"   │ 聚光灯照明，circle mask 衰减，           │
  │               │ 照明图用作高光/阴影贴图                   │
  ├───────────────┼──────────────────────────────────────────┤
  │ "nightvision" │ 夜视仪效果，画面整体绿色，               │
  │               │ 照明图亮度作为可见度 mask                 │
  ├───────────────┼──────────────────────────────────────────┤
  │ "infrared"    │ 红外热成像，伪彩色热力图显示，           │
  │               │ 照明图 R 通道 = 热量值（白=热，黑=冷）   │
  └───────────────┴──────────────────────────────────────────┘

5.2 制作方法

Spotlight 照明图:
  - 底图基础上，用白色圆形遮罩标记聚光灯照亮的区域
  - 其余区域为黑色/深灰
  - 高斯模糊边缘使过渡自然
  - 也可以直接画上灯光投射后的阴影效果

Nightvision 照明图:
  - 灰度图，白=可见，黑=完全不可见
  - 可以在底图基础上提取亮度通道然后调整曲线

Infrared 热力图:
  - 灰度图（只用 R 通道）
  - 白色 = 高温（人体、设备、热源）
  - 黑色 = 低温（墙壁、地板）
  - 中灰 = 环境温度
  - Shader 会自动将灰度映射为蓝→青→绿→黄→红伪彩色

5.3 不需要照明时
  设 light_mode = "none" 并省略 light_image 即可。
  画面将按正常 CRT 效果渲染。


6. 异常图 (Anomaly Image) 制作
============================================================

异常图是在异常事件发生时平滑混合叠加到底图上的画面。

6.1 设计思路
  异常图应该是「底图 + 异常元素」的完整画面。
  比如：走廊底图上多了一个黑影、实验室里多了个发光物体等。
  系统使用 blend 过渡（0→1 渐入，持续一段时间后 1→0 渐出），
  所以异常图和底图的背景部分应该尽量一致。

6.2 制作步骤
  1. 复制底图作为基础
  2. 在底图上添加异常元素
     - 可以是人形轮廓、异常实体、光效、文字干扰等
  3. 保持底图部分不变（避免混合时穿帮）
  4. 如果想让异常只影响局部，只修改局部区域

6.3 可选：异常独立深度图
  如果异常元素在不同深度（如走廊尽头出现了一个人影），
  可以提供独立的深度图让透视效果准确。
  不提供时会复用主深度图。

6.4 可选：异常独立照明图
  如果异常改变了照明状态（如灯突然灭了），
  可以提供独立照明图。不提供时复用主照明图。

6.5 异常触发模式
  在 manifest 中配置每个异常的触发方式：
  - "random": 系统按概率随机触发（适合氛围营造）
  - "trigger": 需要通过触发器动作手动触发（适合剧情事件）
  - "timed": 定时触发（保留字段，暂未实现）


7. Manifest 配置详解
============================================================

在 .scp 故事包的 manifest.json 中添加以下配置：

{
  "camera_system": {
    "cameras": {
      "cam_hallway_01": {
        "name": "走廊监控 #1",
        "location": "东翼走廊 B2F",
        "unlocked": false,
        "online": true,
        "base_image": "cameras/hallway_01/base.png",
        "depth_map": "cameras/hallway_01/depth.png",
        "light_mode": "spotlight",
        "light_image": "cameras/hallway_01/light.png",
        "light_radius": 0.35,
        "light_falloff": 2.0,
        "viewport_size": [0.3, 0.3],
        "viewport_pos": [0.5, 0.5],
        "pan_speed": 0.008,
        "pan_bounds": [0.0, 0.0, 1.0, 1.0],
        "noise_intensity": 0.15,
        "scanline_intensity": 0.3,
        "vignette": 0.4,
        "signal_quality": 0.85,
        "snow_intensity": 0.05,
        "timestamp_visible": true,
        "anomalies": [
          {
            "id": "shadow_figure",
            "image": "cameras/hallway_01/anomaly_shadow.png",
            "depth_map": "cameras/hallway_01/anomaly_shadow_depth.png",
            "trigger": "random",
            "probability": 0.03,
            "duration": 3.0,
            "min_interval": 120.0,
            "effects": ["glitch:0.4", "noise_burst:0.3"],
            "action": "sound:sfx/static_burst.ogg"
          },
          {
            "id": "entity_approach",
            "image": "cameras/hallway_01/anomaly_entity.png",
            "trigger": "trigger",
            "duration": 8.0,
            "min_interval": 300.0,
            "effects": ["shake:0.5"],
            "action": "new_mail:incident_report_01"
          }
        ]
      },
      "cam_exterior_01": {
        "name": "外部监控 A",
        "location": "码头入口",
        "unlocked": true,
        "online": true,
        "base_image": "cameras/exterior_01/base.jpg",
        "light_mode": "none",
        "viewport_size": [0.4, 0.4],
        "noise_intensity": 0.2,
        "signal_quality": 0.7,
        "snow_intensity": 0.1
      }
    }
  }
}

7.1 字段说明

基础字段:
  name            String   显示名称
  location        String   位置描述
  unlocked        bool     初始是否解锁（false 需触发器解锁）
  online          bool     初始是否在线

图像路径（相对于 data/ 目录）:
  base_image      String   底图路径（必须）
  depth_map       String   深度图路径（可选）
  light_image     String   照明图路径（可选）

照明参数:
  light_mode      String   "none"|"spotlight"|"nightvision"|"infrared"
  light_radius    float    聚光灯照明范围 0-1（默认 0.35）
  light_falloff   float    聚光灯衰减指数（默认 2.0）

镜头参数:
  viewport_size   [w, h]   镜头视野占底图比例（默认 [0.3, 0.3]）
  viewport_pos    [x, y]   初始镜头中心位置（默认 [0.5, 0.5]）
  pan_speed       float    方向键平移速度（默认 0.008）
  pan_bounds      [x1,y1,x2,y2]  镜头中心可移动边界（默认 [0,0,1,1]）

效果参数:
  noise_intensity     float  基础噪点 0-1（默认 0.15）
  scanline_intensity  float  扫描线 0-1（默认 0.3）
  vignette            float  暗角 0-1（默认 0.4）
  signal_quality      float  信号质量 0-1（默认 1.0）
  snow_intensity      float  雪花点 0-1（默认 0.0）
  timestamp_visible   bool   显示时间戳（默认 true）

异常配置（数组，每个元素）:
  id              String   异常唯一标识
  image           String   异常底图路径
  depth_map       String   异常深度图路径（可选）
  light_image     String   异常照明图路径（可选）
  trigger         String   触发方式 "random"|"trigger"|"timed"
  probability     float    random 模式每秒概率（默认 0.03）
  duration        float    持续秒数（默认 3.0）
  min_interval    float    最小间隔秒数（默认 60.0）
  effects         Array    附带效果 ["glitch:强度", "noise_burst:强度", ...]
  action          String   触发器动作串（同 trigger_system 语法）


8. 触发器动作
============================================================

在 .meta.cfg 的触发器中可使用以下摄像头相关动作：

  动作                    │ 说明
  ───────────────────────┼─────────────────────────────
  camera_unlock:cam_id    │ 解锁指定摄像头
  camera_lock:cam_id      │ 锁定指定摄像头
  camera_online:cam_id    │ 使摄像头上线
  camera_offline:cam_id   │ 使摄像头下线
  camera_anomaly:cam_id   │ 触发该摄像头的第一个异常
  camera_anomaly:cam_id:anom_id │ 触发指定异常
  camera_signal:cam_id:0.5      │ 设置信号质量（0-1）

示例 .meta.cfg:
  [triggers]
  on_open_security_report = camera_unlock:cam_hallway_01 | sound:sfx/unlock.ogg
  on_enter_level3 = camera_unlock:cam_lab_01 | camera_unlock:cam_exterior_01
  on_read_incident = camera_anomaly:cam_hallway_01:entity_approach


9. 玩家操作指南
============================================================

命令行:
  camera list           列出所有已解锁摄像头
  camera view [编号]    打开指定摄像头（或打开查看器选择界面）
  camera status         显示所有摄像头状态
  cam / cctv            camera 的别名

查看器中:
  ←/→/↑/↓              平移镜头
  1-9                   快速切换摄像头编号
  TAB                   切换下一个在线摄像头
  Q / ESC               关闭查看器

11. 效果强度与安全模式
============================================================

摄像头系统的异常效果受全局 effect_settings 控制：

  效果等级   │ 异常视觉  │ 附带效果(glitch/shake)  │ 触发器动作
  ──────────┼──────────┼───────────────────────┼──────────
  FULL       │ 正常显示  │ 正常执行               │ 正常执行
  MILD       │ 正常显示  │ 衰减 50%              │ 正常执行
  OFF        │ 不显示    │ 不执行                 │ 正常执行

注意：触发器动作（如投递邮件、解锁文件等剧情推进）不受
效果等级影响，始终执行。这确保了玩家不会因为关闭效果而
错过剧情内容。


12. 设计建议与最佳实践
============================================================

12.1 底图设计
  - 底图宽度建议为显示窗口的 3-4 倍，给足平移空间
  - 在底图中隐藏细节（涂鸦、文件、异常痕迹）鼓励玩家探索
  - 不同摄像头可以展示同一空间的不同角度

12.2 异常设计
  - "random" 异常用于氛围营造，概率保持 0.01-0.05 较好
  - "trigger" 异常用于关键剧情节点，由故事触发器控制
  - 异常图的变化幅度越小越诡异（如只是多了个影子）
  - 配合声音效果（action: "sound:..."）增强冲击力

12.3 照明选择
  - 室内有灯光 → spotlight 模式
  - 夜间/停电 → nightvision 模式（氛围好）
  - 特殊设施/SCP 主题 → infrared 模式（科技感）
  - 室外白天 → none 模式即可

12.4 信号质量叙事
  - 降低 signal_quality 制造「信号不好」的紧张感
  - 可通过触发器动态调整：camera_signal:cam_id:0.3
  - 信号很低时雪花点和噪点会自动增加

12.5 解锁节奏
  - 初始只给 1-2 个基础摄像头
  - 随安全等级提升逐步解锁更多
  - 某些摄像头可以是「发现后才解锁」（通过读取文件触发）
  - 下线/上线变化制造时间压力（「这个摄像头突然断了！」）
