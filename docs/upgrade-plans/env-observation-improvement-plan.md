## 1. 已认可的方向与新增要求

- 将 env 改为轻量、有趣、有用的小功能，参考 radio 的操作反馈和发现感。
- 日常流程为“采集 → 查看摘要 → 提交”；感兴趣的疑点可以额外复测、标记和记录。
- 每日基础值班保持简短，深入核对可选，难度低，不依赖专业知识。
- 后续兼容 camera 摄像头功能，支持环境、画面、无线电及文件之间的线索核对。
- 增加岛屿及周边地图，由用户之后手动绘制；地图承载实时扫描与发现反馈。
- 玩家无法移动，外部现场观测与操作由远程控制的无人机承担；玩法参考 Duskers。这是用户补充的已确定方向。
- 无人机为空中飞行，支持指令控制的三维移动；目前没有水下无人机，保留未来扩展方向。
- 采用低面数 3D 地图／白模或简单上色，通过按需渲染与旧式图传后处理生成照片；无人机不向玩家提供实时视频。
- 飞行范围受最低离地高度、最高高度、以站点为中心的半球形通信边界及禁飞区共同限制，具体数值待定。
- 用户补充：场景采用萨哈林岛附近多雾海域的氛围，雾限制无人机可视范围；玩家位于军事管制区，无人机飞得过高会有被击落的后果。作为游戏设定记录，未核实为现实地理或军事规则。
- 具体剧情、岛屿地理、事件真相、分数和扫描设备设定尚未定稿，实施时不得自行补成正式设定。

以下交互和数值为实施建议，便于后续落地调整；不代表全部细节已单独确认。

### 可复用基础

- 现有详细环境仪表盘，作为可选详情保留。
- camera 的注册、解锁、上下线、画面与异常配置。
- radio 的调谐、渐进反馈、隐藏信号发现及书签能力。

## 3. 核心体验

### 日常路径

输入 `env` 打开观测台 → 采集 → 查看今日变化摘要 → 提交日报。

- 建议采集动画约 2～3 秒，复用系统统一进度条。
- 普通日建议 10～20 秒完成；这些是体验目标，后续由用户测试调整。
- 普通日明确显示“暂无待查项目”，允许平静日存在。
- 完成后再次打开显示今日记录，不必重做日常。

### 可选发现路径

查看疑点 → 复测或核对其他来源 → 标记关注／写入日报。

- 同时突出最多一个主要疑点；额外内容放入记录列表。
- 展示“变化是什么、为什么值得注意、怎样核对”，不要求记忆阈值和传感器 ID。
- 复测提供第二份证据，不采用随机成功率。
- 可以如实记录“尚未确认”；不要求猜中隐藏真相。
- 校准仅在证据指向设备偏差时提供，不要求输入专业调整量。
- 同一疑点不会通过反复复测刷出更优结果或重复奖励。

## 5. 岛屿地图与实时扫描扩展

### 用户要求

用户后续手绘地图。系统需要让玩家在地图上实时观察岛上及周边的扫描结果，增加探索和发现趣味。

### 推荐的首版实现

- 地图底图与标记分开：底图替换不会破坏扫描点、摄像头位置和已发现记录。
- 使用归一化坐标定位设施、区域和目标，适应窗口缩放；所有图层共用地图显示变换。
- 先用占位地图开发布局，用户地图完成后替换底图；占位位置不构成正式地理设定。
- 打开地图即可看到当前监测状态；扫描线或扫描圈经过区域时刷新反馈。
- “实时”首先指界面持续显示游戏内当前状态，不要求玩家长时间挂机，也不绑定电脑真实日期决定关键剧情。
- 普通天气变化可以持续更新；每日首次采集生成固定快照，作为日报及判定依据。
- 关键事件按游戏日、剧情条件和事件状态刷新，避免反复进出界面随机重抽。
- 点击标记查看观测摘要、最后观测时间、证据来源及可用核对入口。
- 玩家通过地图下达无人机前往区域、扫描、复测与返航指令；首版建议自动寻路，不要求逐帧驾驶或复杂雷达调参。

### 发现反馈

建议区分以下显示状态，具体命名可调整：

| 状态 | 地图反馈 |
|---|---|
| 已知设施 | 固定图标，可显示所属摄像头或观测区域 |
| 待确认变化 | 模糊区域或位置范围，避免直接揭示目标身份 |
| 已观测目标 | 保留标记与首次发现记录 |
| 已核对／已记录 | 显示对应证据及日报关联 |
| 已消失／已过期 | 当前画面淡出，历史记录仍可回看 |

颜色配合字符／图标和文本说明，不仅依赖闪烁与颜色区分。普通变化使用轻微仪器音效；强故障效果由剧情配置。

### 扫描边界

- 扫描只展示设备或剧情配置允许观测到的信息，不自动识别整座岛的所有秘密。
- 观测范围、盲区、定位精度和不同来源的能力需要后续明确；地图应能显示“未覆盖”和“不确定”。
- 现场操作载体已确定为空中无人机；固定环境传感器、无人机传感器及其他探测来源分别记录。具体载荷与周边海域的观测方式待确认，无水下无人机。
- 周边目标是否移动、是否随时间出现、扫描采用自动轮询还是手动触发，属于待讨论细节。

## 6. camera、radio 与文件联动

### 无人机操作与 Duskers 借鉴（2026-09-30 补充）

玩家始终留在终端前，通过无人机接触外部环境。地图因此同时承担调度、覆盖范围与证据定位功能，扫描信息来自具体设备，不是无来源的全岛全知视图。

参考依据：[Duskers 官方 Steam 产品介绍](https://store.steampowered.com/app/254320/Duskers/)。该介绍明确强调命令行控制无人机和系统，以及通过运动传感器、无人机摄像头等获取信息；也包含设备故障与资源压力。以下取舍是针对 SCRT 的设计建议，不是对 Duskers 全部玩法的复刻。

#### 适合借鉴的部分

- **远程操作感**：选择无人机、指定目的区域、看到位置和任务状态变化。
- **有限信息**：无人机覆盖范围之外仍是未观测区域；地图点位、传感器反馈和摄像头画面各有信息边界。
- **操作带来发现**：派往某一区域后获得新读数或画面，复测可补充证据。
- **简洁指令与终端反馈**：地图按钮和快捷键执行操作，可保留对应命令入口；命令名称待实施时统一。
- **有依据的不确定性**：链路干扰或读数不明应提供可理解的提示和核对方法。

#### 保持低负担的首版建议

- 先提供一台通用无人机，预留多台与载荷扩展接口；数量和型号未定稿。
- 基础日常采集可通过预设巡检一键执行，维持短时值班目标；外部深入核对由玩家选择区域派遣。
- 主要操作为“前往、扫描／复测、返航”；任务状态清楚显示“待命、前往中、观测中、返航中、链路受限”。
- 自动规划路线与执行观测，允许取消和返航。一次可选派遣建议控制在几十秒内，具体节奏由用户体验调整。
- 首版不增加必须管理的燃料、维修材料、装备耐久或永久损失；这些并非已确定的 SCRT 玩法。
- 不加入需要快速输入命令才能生存的日常压力；链路问题优先服务观察和叙事。
- 关闭地图、查看邮件或接听通讯时，无人机任务不会凭空丢失；界面恢复后能回看结果。暂停规则实施前明确。

#### 与 camera 的关系

- 固定 CCTV 和无人机现场画面分别标注来源，可关联同一个区域与事件。
- 有固定摄像头覆盖时可直接核对；没有固定覆盖时可建议派遣无人机，但未覆盖／无法抵达的区域仍保持未知。
- 无人机使用独立 3D 场景中的拍摄相机按需生成静态照片，复用 camera 的部分效果和现有图片查看能力；照片接收不等于接入实时视频。固定 CCTV 的现有行为另行保留。
- “到达区域”不等于“已确认线索”；需要完成配置好的观测或玩家确认动作。

建议闭环：地图出现待查变化 → 下达无人机移动指令 → 现场扫描／拍照 → 接收并查看照片 → 与固定传感器或其他资料核对 → 标记或写入日报 → 返航。

### 3D 拍照与飞行约束（最新确定方向）

- 地图是俯视遥测界面，持续显示位置、任务与链路状态；照片仅代表拍摄时刻，右侧预览改为“最近接收照片”，显示拍摄时间、位置、朝向和高度。
- 3D 场景采用白模或简单材质，优先完成地形轮廓、设施与线索目标。通过低分辨率、灰阶／偏色和适量噪点模拟旧式图传；参考《铁肺》的有限影像体验，不默认照搬其具体机制。
- 拍照时按无人机位置、相机朝向与视场角渲染单帧，再生成独立图像；不持续刷新玩家所见画面。照片与原始拍摄元数据随玩家进度保存。
- 需要独立控制拍摄方向的指令，并预留俯仰角／朝向参数。地图位置、扫描足迹和照片视野应分别表达。
- 无人机由指令控制三维移动，首版优先支持绝对目的地、相对位移、调整高度、拍照、扫描和返航；最终语法待实施统一。

#### 可飞行空间

设站点通信中心为 C、无人机位置为 P、通信半径为 R：基础通信域满足 `|P-C| ≤ R` 且位于约定基准平面的上半空间。站点天线位置与基准面需在建模时确定。

在此基础上再叠加以下约束；实际可飞行域是它们的交集，而不是地图圆内任意高度都可到达：

1. **最低离地高度**：无人机高度减去当前位置地表高度不得低于配置值，按地形变化检查。用机载安全限制与低空链路风险作游戏内解释；不把“所有低空必然受电磁干扰”写成现实物理结论。保护模型近距离细节是开发目标，玩家提示只说明限制原因与允许高度。
2. **最高高度**：军事管制区规定限高，超出存在被击落后果。需明确采用海拔／基准面高度还是离地高度，UI 标注一致；安全限高与击落触发高度是否分开、是否有警告宽限期待定。
3. **通信限距**：按三维距离检查半球边界；高度增加会缩小同高度的水平可达范围。大海域地图的 30 海里是观测显示范围，不自动等于无人机通信半径。
4. **禁飞区**：配置区域轮廓与垂直范围，可用于设施上空、危险区域或未开放区域。永久区与剧情临时区分别标识。
5. **实体障碍**：地形和建筑需要碰撞／路线检查；限高限距不能替代它们。

移动前与移动途中均校验完整路径，禁止仅检查终点而穿过山体、禁飞区或越界。首版建议对不合法指令提前拒绝并说明原因、建议可用高度或目的地；复杂绕障寻路可以分阶段加入。

安全返航作为基础能力，返航路径同样遵守约束。新禁飞区或链路变化影响正在执行的任务时，应停止／暂停并提供明确反馈，处理规则实施前细化，不默认随机坠毁。起降段可由系统执行专用航线，解决最低离地高度与站点停机位置的冲突。

半球形通信范围是本项目的简化玩法模型，不意味着真实链路一定无遮挡；地形遮挡、区域干扰等可作为后续独立扩展。

#### 雾、可视范围与军事管制（用户补充）

- 雾提供可视信息边界：照片中超过当前能见距离的地形和目标逐渐被雾遮蔽，而不是靠任意裁切照片隐藏场景。雾随配置的天气／区域／高度变化，不默认每个场景同样浓。
- 雾不自动等同于通信失联或无法飞行；飞行域、链路覆盖、传感器探测和照片可见范围分别计算。地图已知设施也不因拍照看不清而消失。
- “视距会有最低限制”的具体含义待确认：建议区分玩家可用的最低能见距离（防止照片完全不可读）与最大有效可视距离（限制远距离观察）。暂不填入数值或把这句话解释为新的最低飞行高度。
- 低空安全限制与高空军事限高共同形成可操作高度区间；雾控制该区间内能看清什么。避免玩家升高便能看穿雾或越过军事边界。
- 超高击落是明确的设定方向，发生规则应由高度、区域和持续时间等可解释条件决定，不沿用随机故障概率。
- 为保持低难度，建议普通越界指令默认被安全系统拒绝；如后续允许主动突破安全限制，再以明确警告和确认进入有击落风险的操作。是否提供突破功能、如何触发击落尚未决定。
- 界面需展示当前高度、合法高度范围、雾中预计可视距离及军事管制提示。警告只报告玩家已知的规则，不预先揭露隐藏剧情。
- 若无人机被击落，任务中止、未传回照片、已保存证据、补发无人机或剧情恢复方式均需设计；必要主线不应因一次误操作永久无法推进。
- 本条是游戏限制与氛围方案，不用现实萨哈林海域的天气频率或具体防空规则作为未经核实的事实。

采用统一区域 ID 和事件 ID 关联多个系统，地图不会替代摄像头或无线电的独立操作。

| 联动 | 建议体验 |
|---|---|
| env → camera | 地图选择区域后，打开覆盖该区域且已解锁、在线的摄像头 |
| camera → env | 玩家确认的画面证据加入对应事件记录，返回地图保留原选中位置 |
| env ↔ radio | 环境变化提示值得收听的频段；无线电发现可关联某个观测事件 |
| env ↔ 邮件／Vdisc | 报告和文件引用观测记录，玩家可核对信息是否一致 |
| env → 角色通讯 | 首次发现、日报提交或特定证据组合触发配置好的反馈 |

没有覆盖摄像头、摄像头离线或尚未解锁时，显示原因并允许返回；点击摄像头入口本身不算发现画面证据。

七天试玩版优先提供线索与解释。天气、设备随机变化不应阻断必要剧情；关键线索错过后应有补充入口。联动样例不是正式剧情，事件内容交由写手提供。

## 7. 内容密度与难度

- 首版内容分为普通变化、设备疑点、尚无法解释的变化三类。
- 七天试玩建议安排 2～3 次值得主动核对的事件，其余日子允许正常值班；具体日期由剧情决定。
- 普通变化提供海岛生活感，不强制处理。
- 设备疑点一次复测即可获得有用信息，处理反馈清楚。
- 未解变化鼓励留下记录，通过其他系统逐步补充证据。
- 地图不持续弹出新任务催促玩家，也不要求反复巡查才能完成基础值班。

## 8. 日报、绩效与个人档案

- 每日首次提交日报获得基础绩效，具体分值待确认。
- 主动核对有价值的疑点可获一次额外奖励或发现记录，具体奖励条件待确认。
- 如实写明尚未确认是有效报告。
- 奖励按“玩家／主线进度／日期／事件／奖励类型”去重；读档和重开界面不得重复计分。
- 日报保留首次观测、复测、证据来源、玩家备注、提交结果和得分来源。
- 个人档案未来展示今日及历史绩效明细，能够追溯到日报或事件。
- 新观测记录随玩家进度保存，沿用项目存档体系，不另建需要玩家手动管理的资料库。

### demo：先做环境监视
