一、设计理念
================================================================

1.1 核心灵感

  借鉴 VA-11 Hall-A 的设计哲学:
  - 用"日常工作循环"驱动故事推进（调酒 → 环境监测）
  - 角色在固定场景中来找你，对话自然展开
  - 玩家的主要参与感来自"倾听"而非"选择"
  - 工作本身是有意义的仪式感，而非纯粹的 skip 障碍

  区别于 VA-11 Hall-A 的关键差异:
  - 玩家的"工作数据"本身就是叙事的一部分（异常读数即剧情线索）
  - 不止于对话——文件系统、邮件、无线电信号都是叙事通道
  - 开放给社区作者：任何人都可以制作剧情模组(.scp 故事包)
  - 终端交互的沉浸感：玩家"就是"那个盯着 CRT 屏幕的操作员

1.2 体验目标

  玩家应该感受到:
  ① 我在做一份真实的、有仪式感的工作
  ② 数据背后有什么不对劲——而我是唯一注意到的人
  ③ 屏幕另一头的那些人，有的在帮我，有的在隐瞒什么
  ④ 这座孤岛上正在发生某些超出理解的事情

1.3 设计原则

  · 数据即叙事   —— 环境读数的变化本身讲述故事
  · 日常即节奏   —— 重复的工作给玩家锚点，异变才有重量
  · 被动发现     —— 最好的剧情不是告诉你，而是你自己从数据中看出来
  · 模块化叙事   —— 主线 + 支线 + 社区创作，层层叠加而不冲突


二、核心游戏循环
================================================================

2.1 单日流程

  一天 = 一个"轮班"。每轮班的流程:

  ┌─────────────────────────────────────────────┐
  │  1. 开机启动                                │
  │     └─ 系统自检 → 日期/天气显示             │
  │     └─ 晨间通讯（AVA 或其他角色主动联络）    │
  │                                             │
  │  2. 例行工作                                │
  │     └─ env scan（自动检测，约 30 秒动画）    │
  │     └─ 扫描报告 + 异常标记                  │
  │     └─ （如有异常）角色反应对话              │
  │                                             │
  │  3. 自由探索期                              │
  │     └─ 阅读文件系统中的新文件               │
  │     └─ 查看新邮件                           │
  │     └─ 拨号联络角色（主动对话）             │
  │     └─ 使用无线电接收器扫描信号             │
  │     └─ env view 查看仪表盘细节              │
  │     └─ 探索密码/解锁新区域                  │
  │                                             │
  │  4. 空闲触发                                │
  │     └─ 一段时间无操作 → 角色主动联络        │
  │     └─ 或系统事件触发（邮件/警报/异响）     │
  │                                             │
  │  5. 关闭终端                                │
  │     └─ 自动存档                             │
  │     └─ 下次启动 → 自动进入下一天            │
  └─────────────────────────────────────────────┘

2.2 "工作"的仪式感设计

  env scan 不应该是"按一下跳过"的东西:

  · 进度条的速度适中（总计约 20-30 秒），给玩家时间阅读结果
  · 每一步都有简短的反馈文字，不是空等
  · 异常数据用醒目颜色标记，引导玩家注意
  · 完成后给出简洁但有信息量的汇总
  · 关键: 随着剧情推进，扫描结果本身变得越来越"不对劲"
    （某个读数缓慢偏移、突然出现从未见过的异常类型）

  这与 VA-11 Hall-A 的调酒类似:
  调酒本身不复杂，但你会注意到客人的情绪变化；
  环境监测本身不复杂，但你会注意到数据的诡异趋势。

2.3 自由探索期的内容密度

  每天的自由探索期应有足够内容驱动玩家兴趣:

  · 新文件解锁（权限升级后可见、或由触发器添加）
  · 新邮件到达（延迟投递，模拟异步通信）
  · 角色可拨号联络（每天有不同的对话内容）
  · 无线电信号变化（新的摩斯码/SSTV 图像出现）
  · 文件系统中隐藏的线索（需要密码解锁的文件夹）

  但也不能过载——每天 3-5 个新内容点就够了。
  让玩家觉得"今天看完了"，而不是"还有太多没看"。


三、叙事层次架构
================================================================

3.1 三层叙事结构

  ┌─────────────────────────────────────────────┐
  │  第一层: 表层 —— 日常工作                   │
  │  "我是一名前哨站操作员，负责记录天气数据"    │
  │                                             │
  │  第二层: 中层 —— 异常与疑问                 │
  │  "这些数据不对劲，总部的回复也很奇怪"       │
  │                                             │
  │  第三层: 深层 —— 真相                       │
  │  "这座岛上藏着 SCP 基金会的秘密"            │
  └─────────────────────────────────────────────┘

  玩家从第一层开始，随着天数推进逐渐意识到第二层，
  最终在关键转折点揭示第三层。

  每一层对应不同的叙事通道:
  · 第一层: 环境数据、天气报告、例行邮件
  · 第二层: 异常读数、角色的暗示性对话、加密文件
  · 第三层: 高权限文档、SCP 报告、总部的真实指令

3.2 章节(Act)结构

  整体故事以"章节"组织，每章由若干天组成:

  ──────────────────────────────────────────────
  序章: 适应期 (第 1-3 天)
  ──────────────────────────────────────────────
  基调: 平静、教学
  目的: 让玩家熟悉系统、建立日常感

  · Day 1: 到岗报告。AVA 介绍系统。一切正常。
  · Day 2: 第一次独立操作。数据正常。有一封来自前任的邮件。
  · Day 3: 继续平静。但如果仔细看，某个读数有微小偏移。
           总部回复"一切正常"。

  关键设计: 这几天必须"无聊到正好"——建立基准线,
           让后面的异变有对比参照物。

  ──────────────────────────────────────────────
  第一章: 初兆 (第 4-7 天)
  ──────────────────────────────────────────────
  基调: 微妙的不安
  目的: 种下疑问种子

  · 磁场读数出现无法解释的脉冲
  · 总部的回复越来越敷衍
  · 无线电上偶尔能收到不在记录中的信号
  · AVA 提到"前几任操作员的平均任期是 14 天"
  · 文件系统中发现一个加密目录

  ──────────────────────────────────────────────
  第二章: 暗涌 (第 8-14 天)
  ──────────────────────────────────────────────
  基调: 紧张、发现
  目的: 第二叙事层全面展开

  · 环境异常频率上升
  · 一封标记 [CLASSIFIED] 的邮件误发到你的收件箱
  · 无线电信号中包含坐标和日期
  · 解密加密目录后发现前任操作员的日志
  · AVA 的行为开始出现微妙的不一致
  · 总部突然升级你的权限（为什么？）

  ──────────────────────────────────────────────
  第三章: 真相 (第 15-21 天)
  ──────────────────────────────────────────────
  基调: 揭示、抉择
  目的: 第三叙事层揭开

  · 发现这座"气象站"的真实用途
  · SCP 相关文档可读
  · 总部的真实指令与表面指令矛盾
  · 必须在"服从"和"质疑"之间做出选择
  · 环境数据出现前所未有的异常模式

  ──────────────────────────────────────────────
  终章: 结局 (第 22-28 天)
  ──────────────────────────────────────────────
  基调: 取决于玩家的选择和发现
  目的: 收束叙事线

  · 多结局（基于玩家的信息发现程度和关键选择）
  · 环境数据趋向极端或恢复正常（取决于结局走向）
  · 最后一天的 env scan 数据具有叙事意义

3.3 日配置数据结构

  每天的内容由以下部分组成:

  day_config = {
    "day": 5,
    "act": "act1",
    "title": "第五天 — 安静的早晨",

    // 环境覆盖（让数据讲故事）
    "env_overrides": {
      "force_weather": "fog",           // 强制天气
      "sensor_bias": {                  // 传感器偏移（制造异常）
        "mag_field": 15.0,
        "radiation": 0.02
      },
      "force_events": ["magnetic_pulse"] // 强制触发事件
    },

    // 对话触发
    "dialogues": {
      "on_start": ["day5_morning"],
      "on_scan_complete": ["day5_discovery"],
      "on_anomaly": [],
      "on_idle_300": ["day5_idle_hint"]  // 空闲5分钟触发
    },

    // 内容解锁
    "unlocks": {
      "files": ["/logs/prev_operator_03.txt"],
      "mail": ["hq_weekly_update_2"],
      "radio_signals": ["signal_unknown_03"],
      "passwords": {"deep_archive": "LIGHTHOUSE"}
    },

    // 触发器（基于玩家行为的条件反应）
    "triggers": {
      "on_read_complete:/classified/report_07.txt": "comm:ava_react_report07",
      "on_open_file:prev_operator_03.txt": "delay:3000:new_mail:hq_warning"
    }
  }


四、角色系统设计
================================================================

4.1 角色阵容设计

  ┌──────────┬──────────────┬───────────────────────────┐
  │  代号    │  身份         │  叙事功能                │
  ├──────────┼──────────────┼───────────────────────────┤
  │  AVA     │  AI 联络员   │  导师/同伴/可能的威胁     │
  │          │              │  始终在线，最常互动的角色  │
  │          │              │  后期行为可能暴露其真实目的│
  ├──────────┼──────────────┼───────────────────────────┤
  │  HQ      │  总部管控    │  权威/信息源/可能的谎言    │
  │          │              │  通过邮件和偶尔的通讯出现  │
  │          │              │  代表"组织"的声音         │
  ├──────────┼──────────────┼───────────────────────────┤
  │  前任    │  前操作员    │  "幽灵"角色/过去的声音   │
  │          │              │  通过日志文件和录音出现    │
  │          │              │  发现他/她经历了什么       │
  ├──────────┼──────────────┼───────────────────────────┤
  │  研究员  │  Site 科学家 │  知情者/盟友/或对立面      │
  │          │              │  第二章后开始联络你        │
  │          │              │  拥有关键信息              │
  ├──────────┼──────────────┼───────────────────────────┤
  │  ???     │  未知信号源  │  悬念/恐惧/超自然要素      │
  │          │              │  无线电中偶尔出现的声音    │
  │          │              │  可能不是人类              │
  └──────────┴──────────────┴───────────────────────────┘

4.2 角色出场节奏

  以 VA-11 Hall-A 为参考:
  - 不是所有角色同时出场
  - 每个章节引入 1-2 个新角色
  - 角色之间有关联，对话会互相引用
  - 某些角色会"消失"，消失本身就是剧情

  Day 1-3:   只有 AVA
  Day 4-7:   AVA + HQ（邮件/偶尔通讯） + 前任日志（文件）
  Day 8-14:  AVA + HQ + 研究员（开始联络） + 无名信号
  Day 15+:   所有角色 + 关系变化

4.3 角色对话的日变化

  每个角色每天有不同的对话内容，分为:

  · 主线对话: 推进剧情，不可跳过（on_start 自动触发）
  · 拨号对话: 玩家主动呼叫时的内容（每天不同）
  · 反应对话: 对玩家行为的回应（读了某文件、发现异常等）
  · 空闲对话: 玩家长时间不操作时主动联络

  数据格式（已有系统支持）:
  {
    "day5_ava_call": {
      "title": "拨号 AVA — 第五天",
      "callable": true,     // 可通过拨号触发
      "repeatable": false,
      "lines": [
        {"character": "ava", "text": "...", "speed": 30},
        {"character": "ava", "text": "...",
         "condition": "choice:day5_q1"},  // 弹出选择
        {"character": "ava", "text": "1. 问关于前任的事"},
        {"character": "ava", "text": "2. 问关于异常数据"},
        {"character": "ava", "text": "3. 没什么，再见"}
      ]
    },
    "day5_ava_call_a1": { ... },  // 选择1的分支
    "day5_ava_call_a2": { ... },  // 选择2的分支
  }


五、叙事通道详解
================================================================

  SCRT-Reader 的独特优势: 不止一种讲故事的方式。
  不同的叙事通道适合讲述不同类型的信息。

5.1 通讯对话 (CommManager)

  适合: 即时的、情感化的、角色关系导向的叙事
  感受: 像和真人对话

  · 主动触发: 系统在特定时机推送
  · 被动触发: 玩家拨号呼叫
  · 支持选择/分支
  · 有语音合成效果 + 角色头像
  · 最适合: 揭示角色性格、传递情感、关键转折

5.2 邮件系统 (MailSystem)

  适合: 正式的、延迟的、有层次的信息传递
  感受: 像收到真正的工作邮件

  · 可延迟投递（模拟异步通信）
  · 有优先级标记（normal/high/classified）
  · 可由触发器驱动（读某文件后 → 3秒后收到邮件）
  · 最适合: 总部指令、背景设定、伏笔铺垫、世界观扩展

5.3 文件系统 (FileSystem)

  适合: 深度的、需要玩家主动发掘的叙事
  感受: 像在翻阅真实的机密档案

  · 目录结构本身就是叙事设计（权限分级 = 信息分层）
  · 支持多种模板: article / email / chat / two_page_reader
  · 密码解锁机制（线索散布在其他通道中）
  · 前任操作员的日志、研究报告、SCP 档案
  · 最适合: 世界观构建、深层真相、隐藏线索

5.4 环境数据 (EnvMonitor)

  适合: 渐进的、需要观察力的、非文字叙事
  感受: 像真正的科学家在分析数据异常

  · 传感器读数的长期趋势讲述故事
  · 异常类型的变化暗示正在发生什么
  · 特殊事件（磁暴/海温骤变）对应剧情节点
  · 最适合: 制造不安感、让玩家"自己发现"

5.5 无线电信号 (RadioReceiver)

  适合: 神秘的、碎片化的、需要破译的叙事
  感受: 像在寒冷的暗夜里捕捉来自远方的信号

  · 摩斯码: 需要解码的消息片段
  · SSTV 图像: 模糊的照片/地图/示意图
  · 音频电台: 环境音/加密语音
  · 信号出现和消失本身就是叙事
  · 最适合: 悬念、恐惧氛围、超自然暗示

5.6 通道协同叙事示例

  以"发现前任操作员失踪真相"为例:

  Day 6:  [邮件] 总部发来前任的"调离报告"——看起来很正常
  Day 7:  [文件] 发现前任的日志文件，最后一篇日期中断
  Day 8:  [数据] 前任最后值班那天的环境数据出现极端异常
  Day 9:  [通讯] AVA 说"前任因个人原因调离"——但语气不对
  Day 10: [无线电] 在一个废弃频率上收到一段含糊的求救信号
  Day 11: [邮件] 研究员发来加密邮件: "别相信调离报告"
  Day 12: [通讯] 玩家质问 AVA → AVA 的回答出现矛盾
  Day 13: [文件] 用密码解锁深层目录 → 发现真正的报告


六、玩家能动性设计
================================================================

6.1 "倾听者"而非"决定者"

  与 VA-11 Hall-A 相同，玩家的核心体验是"倾听和观察"。
  但在关键节点，玩家的行为和选择会影响故事走向。

6.2 影响故事的玩家行为

  以下行为被系统追踪，影响后续内容:

  ┌──────────────────────┬──────────────────────────────┐
  │  行为类型            │  影响                        │
  ├──────────────────────┼──────────────────────────────┤
  │  阅读了哪些文件      │  角色对话会引用你读过的内容  │
  │  解锁了哪些密码      │  开启对应的剧情分支          │
  │  对话中的选择        │  改变角色对你的态度          │
  │  是否注意到异常      │  影响 AVA 对你的评价         │
  │  拨号联络的频率      │  影响角色关系亲密度          │
  │  探索的深度          │  决定结局的"信息完整度"     │
  └──────────────────────┴──────────────────────────────┘

6.3 结局分歧设计

  结局不是简单的"好/坏"，而是基于"你了解了多少真相":

  · 结局 A "服从者": 从不质疑，按部就班完成工作
    → 被调离，一切归于沉默（你永远不知道真相）

  · 结局 B "发现者": 发现了部分真相，但选择沉默
    → 带着秘密离开，但总部开始监视你

  · 结局 C "揭露者": 发现全部真相，选择对外传播
    → 高风险结局，成败取决于你的准备是否充分

  · 结局 D "理解者": 发现全部真相，理解并接受
    → 最完整的叙事体验，看到事物的全貌

  结局条件 = 信息发现程度 + 关键对话选择 + 是否完成隐藏任务


七、故事包(模组)扩展架构
================================================================

7.1 内容层级

  ┌─────────────────────────────────────────────┐
  │  第一层: res://data/main/                   │
  │  内置主线剧情（预装，作为范例和基础内容）    │
  │  · manifest.json + dialogues/ + mail/        │
  │  · 提供完整的 28 天主线体验                  │
  │  · 展示所有系统的正确用法                    │
  │                                             │
  │  第二层: .scp 故事包                         │
  │  社区/官方的剧情模组                        │
  │  · 可覆盖/追加主线的任何部分                 │
  │  · 可添加新角色、新对话、新文件              │
  │  · 可修改环境参数和事件定义                  │
  │  · 独立的文件系统内容                        │
  │                                             │
  │  第三层: 玩家存档                            │
  │  记录玩家的个人进度和选择                    │
  │  · 当前天数、已触发事件、已读文件            │
  │  · 对话选择记录、结局条件变量                │
  └─────────────────────────────────────────────┘

7.2 .scp 故事包可定制内容清单

  一个 .scp 故事包可以定义:

  已有能力（现有系统支持）:
  ✓ 虚拟文件系统（目录/文件/权限）
  ✓ 密码表（权限升级密码）
  ✓ 触发器（文件阅读/目录进入/命令执行 → 动作）
  ✓ 邮件（延迟投递、多模板）
  ✓ 通讯对话（角色/对话/选择分支）
  ✓ 无线电信号（摩斯码/SSTV/音频电台）
  ✓ 环境配置覆盖（传感器/天气/事件/异常类型）
  ✓ 视觉效果（glitch/shake/tear/黑屏/重启）
  ✓ 拨号号码簿（角色通讯录）
  ✓ 主题色覆盖

  需要新增的能力:
  ○ daily_dialogues（每日对话触发配置）—— 已实现
  ○ day_configs（每日内容解锁/环境覆盖）—— 待实现
  ○ story_variables（剧情变量，用于条件判断）—— 待实现
  ○ ending_conditions（结局条件定义）—— 待实现
  ○ character_relationships（角色关系追踪）—— 待实现

7.3 模组作者工作流

  1. 创建 manifest.json，定义故事基本信息
  2. 编写虚拟文件系统内容（文档、日志、报告）
  3. 定义角色和对话（comm_characters + comm_dialogues）
  4. 配置每日流程（daily_dialogues + day_configs）
  5. 设置触发器和邮件（条件反应 + 延迟内容）
  6. 调整环境参数（让数据配合叙事）
  7. 打包为 .scp (ZIP) 文件
  8. 放入 vdisc/ 目录即可加载


八、待实现的关键系统
================================================================

  以下是实现完整游戏体验所需的新系统/增强:

8.1 每日内容配置系统 (DayConfig)

  功能: 按天数控制内容解锁、环境覆盖、事件触发
  优先级: ★★★★★ (核心)
  状态: 部分实现（daily_dialogues 已有，需扩展）

  每天的配置应包括:
  · 对话触发（已实现）
  · 文件解锁/添加
  · 邮件投递
  · 无线电信号激活/停用
  · 环境参数覆盖
  · 传感器偏移（制造故事性异常）
  · 强制事件

8.2 剧情变量系统 (StoryVariables)

  功能: 追踪玩家选择和发现，用于条件判断
  优先级: ★★★★☆

  示例变量:
  · "trust_ava": 0-100       // 对 AVA 的信任度
  · "truth_discovered": 0-5   // 发现了多少层真相
  · "hq_suspicion": 0-100     // 总部对你的怀疑度
  · "chose_to_report": bool   // 是否选择上报异常
  · "found_prev_log": bool    // 是否找到前任日志

  对话和内容解锁可基于这些变量做条件判断。

8.3 结局判定系统 (EndingResolver)

  功能: 根据变量和条件决定结局走向
  优先级: ★★★☆☆

  结局条件示例:
  ending_a: truth_discovered < 2
  ending_b: truth_discovered >= 2 AND chose_to_report == false
  ending_c: truth_discovered >= 4 AND chose_to_report == true
  ending_d: truth_discovered == 5 AND trust_ava >= 80

8.4 角色关系系统 (CharacterRelationship)

  功能: 追踪与每个角色的关系变化
  优先级: ★★★☆☆

  · 对话选择影响关系值
  · 关系值影响角色后续对话内容
  · 高关系值的角色会透露更多信息

8.5 每日拨号对话轮换

  功能: 每天拨号同一角色时获得不同对话
  优先级: ★★★★☆

  实现: 角色的拨号对话 ID 根据当前天数自动切换
  如拨号 AVA:
  Day 1 → ava_call_day1
  Day 2 → ava_call_day2
  无特定配置 → ava_call_default
